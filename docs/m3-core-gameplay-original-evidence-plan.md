# M3 核心玩法进度与验收规划

以当前代码、专项原版证据和实际运行的测试为准。

**M3 尚未完成。核心玩法、市场挂牌、基础 AI 和整局存读档已接入；当前重点是原版长期运行等价、完整交互与平台验收。** 不按大类缺口数量推算完成百分比，也不把 unknown、安全拒绝或合法 no-op 当成已确认的缺失玩法。

## 范围与依据

目标是从真实地图新局运行到终局，常用交互可达，并在明确的时间、输入和资源条件下验证存读档后的状态与行为。

原版参考为 Rich4.exe V3.11，image base `0x400000`，SHA-256 `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`。本次读取现有 `rich4/asm`、`rich4/csrc`、`rich4/docs` 证据，未重新通过 IDA MCP 核验 IDB。函数、字段和资源依据统一保留在 [证据目录](evidence/README.md)。

## 已建立的验收边界

- **AI：** [策略对齐](evidence/ai-strategy-alignment.md) 与 [随机流/候选表](evidence/ai-rng-pixel-compatibility.md) 已覆盖全局资源锚点、道路、局部爆炸候选表及八方向投影。现阶段不能笼统称为“全局对象表未实现”。未映射 raw 的安全拒绝、纯 core 人工状态回退和所有动态场景的严格等价仍须区别报告。
- **收容退出：** 按 [原版收容流程](evidence/confinement-special-actor-behavior.md)，返回路线格后还要处理到格效果、五次停步和三次 EA5 倒计时，再交还行动权。真实地图回放驱动这些 app 状态机；当前默认 seed 与 X3 资产目标、自然 AI 日限终局及双运行一致性断言均保留。
- **存档：** 当前写入 v9，并接受 v4–v8 的解码分支；不支持原版 DAT 导入。数据往返保留序列化随机字，运行时 `rich4_game_save_resume` 则按原版 `0x402F99/0x402FA1` 用当前 tick 重新播种。两者分别测试，不能把不同读档时刻的后续轨迹相同作为原版规则。
- **SDL smoke：** 默认配置、固定 seed/逻辑时钟、dummy 音视频；每次独立临时工作目录，显式指定资源、字体与输入配置。菜单 2 帧及游戏 120 帧各运行两次，同时检查最终帧和逐帧摘要链。原版 `0x451801` 的 RGB555→RGB565 转色及当前摘要见 [replay/smoke 证据](evidence/m3-12-replay.md)。smoke 的重复性不等同于原版逐像素等价。
- **掌机：** 已有交叉编译、打包、128 MB 无交换 QEMU 和部分 Onion 真机记录，详见 [Miyoo 文档](../packaging/miyoo/README.md)。这些记录不代表当前源码已完成全部固件、整局、显示/音频及 SD 卡性能验收。

## 完成标准

只有上述原版行为、整局交互、存读档和平台条件都有明确证据时，才关闭 M3。现有 headless 演出使用确定的一帧资源代用品验证状态续接，不能代替 SDL 演出；unknown 不得以近似效果补齐；正式运行的随机字、画面或时钟不得被测试工具强制改写成原版结果。
