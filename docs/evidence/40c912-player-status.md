# `0x40C912` 玩家行动与阻塞状态

- 地址与目标模块：`0x40C912`；`core/player_status.c`。
- IDA 结论：2026-07-12 完整复核；函数大小 `0x308`，恢复原型 `int(int)`。普通玩家 a1=1 仅在 play-state 非零、`0x30` 位清零、`+50..+53` 和 `+54` 全空时返回 play-state；a1=0 在 block/`+54` 时返回 0，仅 `+55` 时返回 -1，否则返回 play-state。特殊槽在 a1=0 且 `+2/+4/+6` 三个状态字节全空时返回 2，其余返回 0。
- 本地证据：[`../../rich4/asm/rich4.asm`](../../../rich4/asm/rich4.asm) 第 12021 行开始区分当前玩家 `<4`，读取玩家记录 `+21`；a1 为 0 时检查 `+50` 和 `+54`，并对状态位 `0x30` 分支；后续基本块读取 `+50..+52` 并伴随文本、随机语音等副作用。
- 镜头边界：`0x40C912` 本身没有直接调用 `0x41D476` 或 `0x40829D`，但它通常由 `0x418C55` 的回合入口调用。对状态非零的当前玩家，`0x418C55` 会先执行 `0x41D546 -> 0x41906A(1) -> 0x417E26(WM_PAINT) -> 0x415E70(0)`；无待处理目标时，`0x415E70` 读取当前玩家的 `0x496B70/0x496B72` 并调用 `0x40829D`。因此监狱/医院状态下，状态文字出现前镜头会以设施内部锚点重新居中；不能从 `0x40C912` 的直接调用图推出“后续回合保留旧视角”。
- 置信度：`confirmed`。
- 测试链接：[`tests/unit/test_player_status.c`](../../tests/unit/test_player_status.c)；纯实现位于 [`src/core/player_status.c`](../../src/core/player_status.c)。
- 副作用分离：原版 `sub_40DD1F`、`sub_44808A`、文本和随机语音调用分别输出 actor refresh、scene refresh、text、voice 领域事件位；纯函数不访问 UI、音频或 RNG。
