# 原版 `SAVE?.DAT` 存档数据清单

## 结论

原版主存档不是按“业务对象”挑字段保存，而是把多块运行时内存直接按固定顺序写入，再追加完整可变地图 blob，以及每名玩家各自的时光机快照和地图副本。

特别需要明确：**5 名特殊角色的完整 `16` 字节记录会写入主存档，也会写入时光机快照；特殊角色方向是记录内 `+0x09` 的字节，因此原版会保存并恢复特殊角色方向。**

主存档固定前缀长 `10059`（`0x274B`）字节，之后的总长度为：

```text
10059 + map_blob_size + num_players * (10008 + map_blob_size)
```

其中 `10008 == 0x2718`，是单名玩家的时光机固定快照长度。

## 证据边界

- 原版写档入口：`0x402FD1..0x403395`；转录见 `../rich4/asm/rich4_save_files.asm:530`，逐次 `_libc_fwrite`。
- 原版读档入口：`0x402AC5..0x402FD0`；转录见 `../rich4/asm/rich4_save_files.asm:100`，逐次 `_libc_fread`。
- 存档槽扫描：`0x403396..0x403639`；转录见 `../rich4/asm/rich4_save_files.asm:862`。
- 时光机采集：`0x44808A..0x448543`；转录见 `../rich4/asm/rich4.asm:66335`，`fcn_0044808a`。
- 时光机恢复：`0x448544..0x448A7D`；转录见 `../rich4/asm/rich4.asm:66700`，`fcn_00448544`。
- 普通/特殊角色结构：`../rich4/asm/player_info.h`。
- 股票结构：`../rich4/asm/rich4_stocks.h`。
- 地图结构：`../rich4/asm/rich4_map.h`，以及 [地图对象解析](40af12-map-object.md)。

2026-11-19 已通过 13338 端口的 IDA MCP 复核固定参考：模块 `Rich4.exe`，32 位 x86，image base `0x400000`，SHA-256 `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`。上述五个函数边界、主存档全部 `fwrite/fread` 调用参数、时光机全部 `memcpy` 长度以及特殊角色方向 `0x498E31` 的读写交叉引用均已与转录汇编对齐。字段用途只有在 IDA、汇编、头文件或既有证据能支持时才命名，未解部分保留为 raw/unknown。

## 文件编码和兼容性

- Win32 x86 原生小端序。
- 浮点数按原生 32 位 IEEE-754 bit pattern 直接写入。
- 没有字段标签、块目录、校验和或 CRC。
- 没有真正的格式版本号；开头只有常量 `0x26`，槽扫描只拿它作有效标记。
- 多个结构包含当时进程中的原始指针值。读档只会重绑活动普通角色的姓名指针和 12 支股票的名称指针；这些指针字节本身仍存在文件中。
- 原版读档路径直接信任若干长度和计数，未见完整文件长度、每次 `fread` 返回值、地图 blob 上界或校验和验证。

### 主文件中容易漏掉、但确实保存的状态

- 特殊角色方向及全部持续状态。
- 五名特殊角色记录全体，而不是只保存当前可见角色。
- 四个普通角色槽全体，而不是只保存 `num_players` 个。
- 当前玩家编号、真人玩家数和完整开局规则。
- 股票历史的环形游标和全部 `12 × 144` 历史值。
- 新闻/命运的抽取游标以及洗牌顺序，不能只保存“已经过多少天”。
- 监狱、医院、乐透号码所有权等全局占用表。
- 地图旋转方向、地图访问标记、角色选择/占用标记。
- 整份可变地图内存，包括当前尚未命名的字节。
- 每名当前玩家的时光机快照；即使某个快照的 valid 字段为 0，原版仍把该 `0x2718` 块和地图副本写入文件。

## 特殊角色记录：16 字节

原版保存五份，主存档和时光机快照的布局相同。

IDA 复核到的直接证据：写档在 `0x40308A..0x403094` 以 `count=5, size=0x10, ptr=0x498E28` 调用 `fwrite`；读档在 `0x402BB7..0x402BC1` 使用相同参数调用 `fread`；时光机采集在 `0x4480FF..0x448132` 复制 `0x50` 字节，恢复在 `0x4485C7..0x4485FA` 复制回 `0x498E28`。方向字节 `0x498E31 + slot*0x10` 的读写交叉引用位于 `0x408A7B`、`0x40C719`、`0x40C86A`、`0x40C876`。

| 记录偏移 | 长度 | 数据/已知用途 |
|---:|---:|---|
| `+0x00` | 2 | X 坐标 |
| `+0x02` | 2 | Y 坐标 |
| `+0x04` | 2 | 当前路线节点/`f4` |
| `+0x06` | 2 | 前一节点或移动相关节点/`f6` |
| `+0x08` | 1 | 所属/救援玩家等 raw 状态；精确语义依角色类型而异 |
| `+0x09` | 1 | **特殊角色方向**；汇编按 `0x498E31 + slot * 0x10` 访问 |
| `+0x0A` | 1 | 活动/监禁/禁用 guard raw 值 |
| `+0x0B` | 1 | 返回来源/类型 raw 值 |
| `+0x0C` | 1 | 冬眠/睡眠天数 |
| `+0x0D` | 1 | 梦游天数 |
| `+0x0E` | 1 | 停留天数 |
| `+0x0F` | 1 | 乌龟行走天数 |

因此，自定义保存格式如果没有为特殊角色方向建字段，或者只保存坐标/节点/状态倒计时，就是相对原版的明确缺项。

原版为每名普通玩家固定保留 7 项，共 `4 × 7` 项。创建路径 `0x4246C5`、有效性检查 `0x42483E`、购买路径 `0x4255DA`、删除压缩 `0x4247D5` 和月度老化 `0x428475` 共同确认了全部 12 字节：

| `+0x0A` | 1 | 地产/设施挂牌时的记录类型快照（原地图记录 `+0x18`）；非资产为 0 |
| `+0x0B` | 1 | 地产/设施挂牌时的等级快照（原地图记录 `+0x1A`）；非资产为 0 |

资产出售前，`0x42483E` 同时核对 owner、类型快照和等级快照；任一不一致就删除并压缩挂牌。`+0x01` 虽然在本版本中不影响成交，但仍是原版明确写入、月结明确更新并随存档/时光机往返的状态。

## 可变地图 blob

原版不是只保存“已购买地产”或少数字段，而是把 `0x47493C` 指向的整块 `M` 字节内存写入。开头 `40` 字节是五组 `(count, relative_offset)`：

| 表头偏移 | 内容 | 记录宽度 |
|---:|---|---:|
| `+0x00/+0x04` | 路线节点数量/相对偏移 | 40 |
| `+0x08/+0x0C` | 普通地产数量/相对偏移 | 52 |
| `+0x10/+0x14` | 设施数量/相对偏移 | 56 |
| `+0x18/+0x1C` | 公司/商业地产数量/相对偏移 | 52 |
| `+0x20/+0x24` | 特殊地点数量/相对偏移 | 28 |

计数不含哨兵项，运行时索引通常从 `1` 到 `count`；分配表时包含额外的第 0 项。`0x407AD2` 读取表头并按最后一项末端计算整个 blob 长度。下表是对固定参考可执行文件全部解码写指令的审计结果；“运行期写入”列以外的记录字节只由地图资源装载/初始化产生，没有找到游戏过程中修改它们的路径。

| 表/宽度 | 字段布局 | 已确认的运行期写入 |
|---|---|---|
| 路线 `40` | `+0/+2` 坐标；`+24..31` 四邻接；`+32` 对象 raw ID；`+34` 显示块；`+36..39` flags | `+36..39`；道路道具、路障和路线状态修改 |
| 普通地产 `52` | `+0/+2` 坐标；`+4..22` 名称/静态；`+23` 临时价格/关闭状态；`+24` 类型/连锁；`+25` owner；`+26` 等级；`+27` 变体；`+28` 基价；`+30` 每级价；`+32..43` 六档收费；`+44` 运行值/收费累计；`+48` 租期/到期日 | `+23..26`、`+28..29`、`+44..51` |
| 设施 `56` | `+0/+2` 坐标；`+4..23` 名称/静态；`+24` 类型；`+25` owner；`+26` 等级；`+27` 变体；`+28` 临时价格/关闭状态；`+29` 研究项目；`+30` 研究剩余回合；`+31..33` 静态/raw；`+34` 基价；`+36..47` 六档收费；`+48` 运行值；`+52` 到期/最后变更日 | `+24..30`、`+34..35`、`+48..55` |
| 公司 `52` | `+0/+2` 坐标；`+4..23` 名称/静态；`+24` 董事长/owner；`+25` 股票索引；`+26` 商业类型；`+27` 变体；`+28..31` 前四名股东；`+32` sprite；`+34` 基础费；`+36` 公司价值；`+40` 本期业绩；`+44` 累计业绩；`+48` 可认购股数 | `+24`、`+28..31`、`+40..51` |
| 特殊地点 `28` | `+0/+2` 坐标；`+24` 变体；`+26` sprite；其余静态/raw | 未找到运行期写入 |

关键写路径包括：月结 `0x41CF67` 更新地产/设施状态和到期 owner；设施研究日更 `0x41C84F` 更新 `+29/+30`；公司股东排序 `0x4294D5` 更新 `+24/+28..31`；公司认购 `0x428D2A` 更新 `+48`；公司业绩写入 `0x41D2C6`、`0x42E931`、`0x44B374` 等；新闻和卡片路径更新价格、类型、owner、等级及日期。

因此需要区分两个目标：原版文件的**逐字节复制**必须保留整份 blob；活动局的**行为等价重建**则可以从 stage/map 的静态记录重建未写字节，并独立保存上表全部运行期可变范围。对固定参考可执行文件，未命名字节已经由写入路径审计证明不会在游戏过程中变化，不再属于“未知可变状态”。

## 存档槽扫描实际读取的数据

原版依次尝试 `SAVE1.DAT` 到 `SAVE5.DAT`。槽列表只读取：

1. `0x26` 标记；不匹配则视为无效槽。
2. 4 字节日期。
3. 2 字节地图编号。
4. 2 字节关卡编号。
5. 4 字节玩家数。
6. 四份 104 字节普通角色记录，用于显示日期、地图/关卡缩略信息和角色头像。

槽扫描不验证尾部是否完整，也不验证 checksum/version。因此“能出现在槽列表”不等于“整份文件可安全完整读入”。

## 读档后的修复/重建，而非文件字段

主文件读完后，原版还执行以下操作：

- 对 `0 .. num_players-1` 的普通角色，按 `character` 从静态角色表重绑 `name_ptr`；未启用普通角色槽的原始指针不会进入这段循环。
- 按 `(stage * 4 + map) * 12 + stock_index` 从静态表重绑 12 支股票名称指针。
- 按地图 blob 头的五组计数/相对偏移重建运行时表指针。
- 为每名玩家分配并读入一份 `M` 字节时光机地图副本。
- 调用 `0x407AD2` 一类地图资源初始化路径重建资源/派生链接；这不意味着可省略文件里的特殊角色记录。
- 标记当前玩家 actor/renderer 需要刷新。
- 使用 `GetTickCount()` 调用 `srand()`，重新播种 C RNG。

## 原版主存档明确没有保存的内容

- C RNG 的 seed 或完整随机流状态；读档后以 `GetTickCount()` 重播种。
- UI 当前打开面板、鼠标悬停、输入框编辑过程等界面瞬态。
- 音频播放进度和屏幕/FLC 动画的当前帧。
- renderer、sprite、资源句柄等可由加载/刷新路径重建的运行时对象。
- 日期结构中的 `dayofweek`（主文件只写日期结构开头 4 字节）。

“原版没存 RNG 状态”不能推导为 SDL 也必须丢弃 RNG。若 SDL 目标包含确定性 replay，额外保存自己的确定性状态可以是合理扩展；但扩展不能替代或遗漏上述原版业务状态。

## 对 SDL 自定义格式的最低核对规则

修复/升级自定义保存格式前，至少应逐项证明：

- 主局表中的每一块原版状态都有对应字段，或有明确、可测试的派生重建规则。
- 四名普通角色、五名特殊角色、46 个动态对象全部覆盖；特殊角色方向必须往返一致。
- 新闻/命运“游标 + 顺序表”同时保存。
- 股票“当前记录 + 玩家持股 + 历史 + 历史游标”同时保存。
- 地图中的所有可变记录被覆盖；未知原始字段不能因当前代码没有命名就静默丢弃。
- 每名玩家的时光机快照和对应地图副本都能往返；不能只保存当前玩家的一份。
- 读档后需要重绑/重建的派生对象有独立恢复步骤。
- 格式扩展和版本迁移测试建立在这份基线清单上；不能先定版本号，再反过来猜本次还漏了什么。

当前证据置信度：**physical layout 已确认**（固定参考 IDB 的 `fwrite/fread/memcpy` 参数相互镜像，偏移和长度重新计算一致）；**影响后续玩法的运行期可变内容已逐块分类**。仍保留 raw/保留名称的字节不是遗漏：普通角色 `f58/f67` 在本可执行文件中没有指令引用，地图其余 raw/padding 没有运行期写入。尚缺的是用真实原版 `SAVE?.DAT` fixture 做自动逐字节解析回归，这影响测试强度，不改变上述布局和引用结论。
