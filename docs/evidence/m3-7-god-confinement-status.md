# M3.7 神明、监狱、医院和持续状态证据

## 固定模块与复核

- 模块：`Rich4.exe` V3.11，SHA-256 `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`；2026-07-16 通过 IDA Pro MCP 与 `../rich4/asm/rich4.asm` 交叉复核。
- 玩家记录为 104 bytes：`+52/+53` 是监狱/医院倒计时，`+61` 是玩家关系持续日数，`+63` 是附着动态对象的 one-based 槽号，`+65` 是 one-based 关联玩家。核心协议把 `+65` 转成零基 `linked_player`，并把动态对象槽与对象类型分开保存。
- `0x41C84F` 分离状态 tick 与 pending handler：普通倒计时减到零后写 `0x80`；下一次 handler 阶段才调用 `0x43D7BF`、`0x43EE6E` 或 `0x40CC1A`。
- `0x40CC1A` 清双方 `+61/+65`。它不读写 `+63 god_info`；本步修复了旧实现把两者混用的问题，SDL runtime 的关系 tick 也改为读取 `linked_player`。

## 监狱与医院

- `0x43D593`：普通玩家首次入狱时移除旧路线占用，节点改为 `ref_0048BAE0`，清路径字段，写 `+52`，并设置监狱占用；重复进入只累加天数并保留低 7 位。`0x43EC3F` 是使用 `ref_0048BAE2/+53` 的平行医院流程。
- 两个首次进入分支都在写入专用节点后，以该节点坐标调用 `0x41D476(x,y,0)`，再调用 `0x44EF41` 播放监狱/医院角色语音。因此角色、镜头和固定屏幕语音气泡必须先同步到监狱/医院节点；不能继续使用事件发生前的插值坐标。
- 地图初始化以路线对象原始 ID `0x1F42/0x1F41` 分别发现监狱/医院节点。`rich4_map_data_special_place_nodes` 完成这一适配，核心不会猜默认节点。
- `0x43D7BF/0x43EE6E` 对普通玩家清占用并通过 `0x40D6BE/0x40B93B` 恢复 actor，位置留在专用节点；对特殊角色则移动到专用节点并设置路线 actor type 1/2。
- `core/confinement.[ch]` 把进入和释放做成独立事务。进入提交节点、路径字段、倒计时、逻辑 actor type、累计天数以及 status/actor/scene/text/voice 事件；释放提交计数清零、actor 恢复和 dirty/scene 事件。事件队列不足时状态逐字节不变。
- 特殊角色进入时保存独立 confinement 状态并清其四项持续状态；释放时写专用节点及 actor type 1/2。未在核心中加入瞬时坐标、动画帧或资源句柄。
- 医院探访表现按 `0x43D88F/0x43DA27` 补齐：`Panel[65]` 护士左右姿态、100 ms 手臂/口型动作、原气泡与四段护士语音均由 SDL 临时状态维护；特殊人物获救时在释放提交后播放 `Panel[64]` 离场形象及 `#0124/#0125/#0123/#0126` 语音，再进入护士送别。普通玩家没有额外获救台词。

## 不可控状态与回合入口

- `0x418C55` 在显示人类控制或执行 AI 预行动之前先调用 `0x40C912(0)`。玩家 `+50..+53` 任一状态或 `+54` 冬眠非零时返回 0；case 0 再调用 `0x418E7F`，而后者的 `0x40C912(1)` 仍返回 0，因此不会进入 `0x41982D` 的路线/投骰处理。
- `+55` 梦游是不同分支：`0x40C912(0)` 自己调用 `0x40DD1F` 并返回 -1，属于系统自动行动，不等待人类点击投骰。
- SDL 回合轮换现在统一先标记新玩家 dirty，再执行同一状态判定；监狱、医院、冬眠、消失及延迟阻断状态隐藏投骰面板并轮转，梦游直接进入自动投骰。`game_dispatch.c` 还在指令边界拒绝这些状态下的闲置期控制命令，防止快捷键或其他 UI 绕过。
- 非移动状态下，ViewModel 以 `player.node` 的路线坐标为角色权威位置；只有实际移动期间才使用 `visual_x/visual_y` 插值。这覆盖入狱、住院和其他原版直接改节点的事件。

### 同日起飞锚点纠正：获得节点不等于玩家当前节点

- 上述第一轮接线仍从动态对象 `node` 取得静止时的世界坐标；附身后该字段可能保留获得神明的节点，因此起飞点和镜头一起错误地回到获得地点。`0x40E384` 明确传入玩家 `+8/+10` 当前坐标，附身绘制分支 `0x408FCC/0x408FE5` 同样读取玩家坐标，不使用神明节点。现改为静止时取玩家当前路线节点，移动时取演员的当前插值坐标，再应用原版身后偏移。
- 镜头核实：`0x41D476(x,y,4)` 在目标坐标等于当前行动者时清 `0x48BE18`，否则置 override 并保存目标坐标；`0x415E70` 以该中心调用 `0x40829D`。送神流程再由 `0x40B066` 读取重建队列里的神明锚点。它会重新定位画面，但不会自动旋转地图；`0x417E26` 的 `WM_PAINT` 分支不写旋转全局，写该全局的是旋转按钮分支 `0x418722/0x41874B`。
- 回归改为通过真实 `rich4_app_begin_dynamic_god_detach` 建立演出，不再手工填写正确的起飞坐标。获得节点、玩家当前节点、静止演员缓存坐标刻意不一致，覆盖 8 地图旋转 × 8 朝向 × 静止/移动；对照普通附身绘制队列，要求离场锚点和初始 chunk 完全相同，并验证镜头定位目标玩家、保留旋转方向。`test-god-regression`、`test-god-sdl` 和 `sdl` 均通过。此前测试未覆盖旧节点场景，不能据其通过认定该场景已对齐。
