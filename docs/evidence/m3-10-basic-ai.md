## 原版 AI 道具选择与目标规则

复核日期：2026-10-08。依据当前 Rich4.exe IDA Pro MCP 的反编译、指针表和共享尾部汇编。以下记录原版规则；SDL 实现完成度按独立的实现与验证记录核对。

### 入口、库存与尝试顺序

`0x418C55` 在股票、资金与挂牌阶段后，以一次 `rand() & 1` 选择卡片或道具分支：值为 1 调用 `0x441BAA`，值为 0 调用 `0x447D97`，所选分支执行后继续回合。

`0x447D97` 的自动道具分支要求玩家 `+21` 控制字节满足 `&6 != 0`，且 `+22` 行动设置满足 `&2 != 0`。库存基址为 `0x49915C`，每名玩家占 15 bytes。按编号 1..13 枚举数量非零的道具，跳过 ID 10 时光机；每种道具加入候选一次。

候选数 N 为 1..4 时从首项开始，大于 4 时以 `rand()%N` 选择起点。最多执行 4 次 `0x420E9A(id)`，每次失败后递增索引，到 N 时回到 0。候选数为 1..3 时保留环形重复尝试，例如两项列表的失败顺序为 A、B、A、B。返回值等于 1 时，显示 1500 ms 使用文字，调用实际道具 handler，并结束本次选择。汇编依据为 `0x44800F..0x448085`。

### 难度与真实分发表

`0x420E9A` 计算 `道具难度 - 玩家+23策略值`。差值至少 2 时返回 0；差值为 1 时仅 `rand()%3==0` 进入道具判定；差值至多 0 时直接进入道具判定。`+23` 位于 `0x496B7F + 104*player`，策略值为 0、1、2。

元数据记录为 `0x47FEDA + 8*id`，难度取记录 `+7`。IDA 符号 `funcs_420EE6` 的分发表实际位于 `0x47539C`；实际使用函数指针位于 `0x475DD5 + 4*id`。

### 状态字段、路线窗口与对象表

下文 p 为当前玩家编号，自有 owner 值为 p+1，无主 owner 为 0。地产记录长 52 bytes，设施记录长 56 bytes；两类记录的 `+24/+25/+26` 分别为类型、owner、等级。

| 简记 | 原版字段 |
| --- | --- |
| C：现金 | `0x496B84 + 104*p`，玩家 `+28` |
| B：存款 | `0x496B88 + 104*p`，玩家 `+32` |
| P：物价指数 | `0x4990E8`，IDA 符号 `lpBuffer__20` |
| I：投资修正 | `0x496BAE + 104*p`，玩家 `+70`，有符号 16 位 |
| 慢行状态 | `0x496BA1 + 104*p`，玩家 `+57` |
| 附身对象槽编号 | `0x496BA7 + 104*p`，玩家 `+63` |
| 点券 | `0x496B98 + 104*p`，玩家 `+48`，无符号 16 位 |
| T：交通方式低两位 | `0x496B79 + 104*p`，玩家 `+17`；0/1/2/3 为步行/机车/汽车/工程车 |

- `0x40B221(p,n)` 从玩家路线 `+4` 当前节点开始，初始避开 `+6` 节点，写入 `0x48B8B4` 路线窗口。四个邻接槽分别进入合法边候选；多条合法边时随机选边并设置分岔标记，零条时使用前一节点。最多生成 8 步。
- `0x40B343(p,n)` 从路线 `+6` 节点开始，初始避开 `+4` 节点，其余选边规则与上述窗口相同。地雷、定时炸弹及路障第二阶段调用该函数生成六节点窗口。
- `0x409EF9()` 收集当前视口 29×29 网格范围内、道路 flags 满足 `&0xFFFF00 == 0` 的节点，将节点编号写入 440×440 锚点表。同像素后写节点覆盖前写节点，随后按 y/x 行优先顺序压平到 `0x48B8C4`。
- `0x40A45C(-1)` 通过 `0x409DE7` 建立当前全屏 440×440 对象表，并按行优先顺序收集非零项；同像素 raw ID 按位 OR。
- `0x40A0B1(x,y,r)` 以指定坐标建立局部锚点表，来源为当前 AI 的有效人物位置和有主地产/设施；按写入顺序覆盖同像素项。r=100 扫描中央 200×200 区域，r=-1 扫描 440×440 区域。
- `0x48BE64` 保存选择结果，`0x420EEE(0)` 读取结果。各道具按自身协议解释道路节点、资产 raw ID、人物掩码或骰值。

### ID 1：机器娃娃

`0x420EFA` 调用 `0x40B221(p,4)`，要求四步窗口的分岔标记为 0。逐项读取节点 flags bits 16..21 对应的动态槽，任一对象满足以下条件即返回 1：

- 动态类别为 5、6、7、8、11。
- 动态类别为 17，底层地产/设施 owner 为 p+1。
- 动态类别为 16，底层地产/设施 owner 非零且与 p+1 不同，价值比较量严格大于 `3000*P`。地产比较量为 `0x419744(owner,name)` 返回的同名普通地产当前收费合计；设施比较量固定赋值 10000000。

`0x446AFB` 从当前玩家的位置、路线节点和方向建立机器娃娃 actor 状态。

### ID 2：路障

`0x42107F` 第一阶段调用 `0x40B221(p,4)`；分岔标记为 0 时，按窗口顺序检查 flags 满足 `&0x3FFF00 == 0` 的节点，取首个通过者：

- 无主地产：同名自有地产数量至少 2，或该目标等级非零；并且 `C+B>10000`、`I>=0`、慢行状态为 0、`P*地产[+28]<C`。
- 无主设施：`C+B>10000`、`I>=0`、慢行状态为 0、`P*设施[+34]<C`。
- 特殊道路：flags 低字节 action 为 15，且点券严格大于 200。

第一阶段未选中时，调用 `0x40B343(p,6)` 和 `0x409EF9()`，按可见表顺序检查六节点窗口中的自有地产。评分为 `0x419744(p+1,name)`：同名、type=0、自有地产的当前等级收费之和乘 P。评分严格大于 `6000*P` 且严格大于当前最佳值时更新目标，同分保留首项。成功结果为道路节点编号。

### ID 3：地雷

`0x4213C5` 将 `0x40B343(p,6)` 窗口与 `0x409EF9()` 可见道路表相交，按可见表顺序扫描。节点满足以下任一条件时立即选中：

- 监狱节点 `0x48BAE0`，且 `DWORD[0x496B30] != 0`。
- 医院节点 `0x48BAE2`，且 `DWORD[0x496B60] != 0`。

两个 DWORD 分别打包前四名普通玩家的监狱/医院收容标记；节点映射由 `0x407AD2` 的 raw 8002/8001 初始化及 `0x43D304/0x43E9A4` 收容数组访问确认。

普通候选为 owner 非零且与 p+1 不同的地产/设施对应道路节点。优先分支未命中时，从普通候选以 `rand()%count` 选择一个。结果为道路节点编号。

### ID 4：定时炸弹

`0x421574` 使用与地雷相同的六节点窗口、可见表交集和收容节点优先条件。普通候选收集交集中的全部道路节点，以 `rand()%count` 随机选一个。成功结果为道路节点编号。

共享尾部 `0x42153A..0x421573` 完成随机选择、结果写入和成功标记返回；反编译中的跨函数跳转按该汇编尾部解释。

### ID 5、6：机车与汽车

- 机车 `0x421644`：`T==0 && rand()%4==0` 时通过。
- 汽车 `0x421675`：`T<2 && rand()%4==0` 时通过。

实际使用作用于当前玩家的交通状态。

### ID 7：飞弹

`0x421717` 先调用 `0x40D2D3(p)`：按活动对手编号递增，选择关系字段 `玩家+76+4*对手编号` 中严格最大的正值，同值保留先项。该函数返回 -1 时，调用 `0x40D31C(p)` 从其他活动且 `0x496B9A + 104*对手编号` 为 0 的玩家中随机选择一人。

随后在 `0x40A45C(-1)` 表中寻找含该玩家低四位 bit 的高位人物掩码，写入结果。以目标玩家坐标调用 `0x40A0B1(x,y,100)`，逐项检查 200×200 局部对象表；任一项带 `0x8000` 人物标记，或被 `0x4216AB` 判为自有地产/设施时返回 0。全窗口通过时返回 1；本次判定固定使用已选玩家。成功结果为人物掩码。

### ID 8：遥控骰子

`0x421827` 的前置条件为：附身槽编号处于 `{7,8,15}` 之外、慢行状态为 0、`C+B>=10000`、`I>=0`，并且 `0x40B221(p,6)` 的分岔标记为 0。

按六步顺序扫描。节点 flags bits 12..15 非零时跳过；动态类别属于 `{5,6,7,8,10,11,16,17,18}` 时跳过。其余候选规则如下，表内价格均读取无符号 16 位值，常量 `double[0x463D48]=2.5`：

| 对象 | 条件 | 更新规则 |
| --- | --- | --- |
| 无主地产 | 同名自有地产数 >1；`2.5*地产[+28]<C` | 写入步序 1..6，立即结束扫描 |
| 自有地产 | type=0、level<5、同名自有地产数 >1；`2.5*地产[+30]<C` | level 严格大于最佳等级时暂存步序；初始最佳等级为 0 |
| 无主设施 | `2.5*设施[+34]<C` | 写入步序，立即结束扫描 |
| 自有设施 | type 处于 0/3 之外、level<5；`2.5*设施[+36]<C` | 写入步序，立即结束扫描 |

自有地产最佳等级为 1..4 时使最终判定通过，同等级保留较早步数；后续立即结束型候选可覆盖暂存步序。零价格在正现金下满足严格价格比较。实际使用函数把选出的步序写入一次性骰值。

### ID 9：机器工人

`0x421BA6` 扫描 `0x40A45C(-1)` 全屏对象表，最佳评分初始为 0：

- 自有地产：type=0、level<5，评分读取 `地产[+32+2*level]`。
- 自有设施：level 小于 `byte[0x474940+type]`，评分读取 `设施[+36+2*level]`。类型 0..4 上限依次为 1、5、5、1、5。

评分严格大于最佳值时更新结果；最佳评分为正时返回 1，同分保留行序首项。成功结果为地产 raw ID 2000+索引或设施 raw ID 4000+索引。`0x40B110` 对 AI 自有 0 级设施以 `rand()%4+1` 选择类型，再建设第一级。

### ID 10：时光机

`0x447D97` 的自动候选列表跳过 ID 10；其 AI 判定函数 `0x420EDF` 固定返回 0。真人使用由 `0x447387` 执行会话快照恢复。

### ID 11：传送机

`0x421CB6` 按 `0x409EF9()` 可见道路表顺序读取节点关联资产，保留：

- 无主普通地产：type=0、level>=3、`P*地产[+30]<C`。
- 无主设施：type 非零、level>=3、`P*设施[+36]<C`。

以 `level>best_level` 更新结果，同等级保留首个行序候选。选到目标后，`C+B>10000 && I>=0` 时返回 1。结果为目的道路节点。`0x447428` 的 AI 分支构造当前玩家自身掩码作为传送源，读取上述目的节点执行移动。

### ID 12：工程车

`0x421E20` 要求 T 处于 0..2，然后以 `rand()%15 <= 玩家+23策略值` 判定。函数内部策略值 0/1/2 的通过率依次为 1/15、2/15、3/15；实际进入该函数还须通过难度 2 的共同门槛。效果作用于当前玩家。

### ID 13：核子飞弹

`0x421E62` 先按地产索引、再按设施索引，收集全地图 owner 非零且与 p+1 不同、level 非零的资产 raw ID。最多执行 10 次 `rand()%count` 有放回抽样，首个通过者即选中。

```text
Ns / No < 1 / (A + 2)
Ls / Lo < 1 / (A + 2)
```
