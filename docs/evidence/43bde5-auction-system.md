# 0x43BDE5 拍卖系统：流程、规则、资源与实现

## 证据边界

- 原版主入口：`0x43BDE5`；Win32 模态回调：`0x43A2DD`；AI 估价：
  `0x439F0D`；现金结算：`0x41D2C6`。
- 本文按 IDA Pro MCP 的反编译、交叉引用和静态数据读取结果记录。
  原入口从全局 `0x48A05C` 读取资源 26；该 handle 已在 `0x4015D6`
  确认为 `Panel.MKF`，不是 `Data.MKF`。
- 地图选择 word `0x4991B8`（反编译名 `lpBuffer__0`）和场景选择 word
  `0x4991B6`（`lpBuffer__1`）会以 `map + 4*stage` 选择 `JUMP.MKF`，
  并共同决定拍卖标的图块。因此 SDL 对应字段为 `GameState.map` 与
  `GameState.stage`。

## 入口与所有权政策

共享入口参数语义为 `(seller, raw_property_id, manage_music)`；土地原始 ID
为 `2001..3999`，设施原始 ID 为 `4001..5999`。

| 来源 | seller | manage_music | 未成交所有权 |
|---|---:|---:|---|
| 拍卖卡 | 出牌玩家 | 1 | 卡片入口在返回失败时清除原所有者 |
| 新闻事件 7 | -1（系统） | 1 | 保持不变 |
| 魔法屋动作 11 | 目标玩家 | 1 | 保持不变 |
| 破产清产 `0x40CD87` | -1（系统） | 由外层统一播放 | 清产前已经全部置为无主 |

拍卖卡不会先把价款直接转给出牌者。它把
`base_price * price_index * (level+2) / 5` 写入原所有者对出牌者的关系账，
再进入共享拍卖；卡片无论成交与否都消耗。破产路径先清空土地、设施所有者并
收集标的；剩余活动玩家不止一名且仍有人类玩家时，只有标的数严格大于 3 才
从中无放回随机抽取恰好 3 个拍卖，3 个及以下一个也不拍。

## 开拍、资格与底价

土地和设施使用相同底价：

```text
reserve = price_index * base_price * (level + 2) / 2
```

活动玩家按槽位 0..3 加入。卖方不能参加；现金必须严格大于底价。以下任一状态
也会排除：住宿/延迟状态、消失、坐牢、住院、冬眠、梦游。原函数按上述顺序
覆盖席位状态，最后再以“卖方”覆盖；现金不足显示现金而不是状态文字。
地产当前所有者并不自动排除，所以只要他不是 seller，允许买回自己的地产。

无人合资格时，播放未成交语音后返回。即使只有一名合资格玩家，也必须实际按
一次竞价（AI 的任何非 PASS 选择会被收敛为加 100），不会按底价自动成交。

## 竞价状态机

回调以 100 ms 定时器推进：

1. 播放 `Speaking.MKF[131]` 开场。
2. 播放 `Speaking.MKF[132]` 并报出底价。
3. 从第一个合资格席位开始轮转；真人显示 7 个按钮，电脑立即决策。
4. 每个动作播放 `Effect.MKF[63]`，人物基础资源逐帧反馈，完整动作阶段为
   10 个 tick，约 1 秒；第一个 tick 起在动作玩家行显示反馈气泡，内容是
   当前价、全角 `ＰＡＳＳ` 或 `放棄`。
5. PASS 只对本轮有效；任意有效加价会清除所有 PASS。Give Up 永久退出。
6. 若仍有竞价者则轮到下一席；只剩一名且已有领先者时成交，无领先者则未成交。
7. 成交时播放 `Effect.MKF[29]` 和 `Speaking.MKF[135]`，再播放
   `Speaking.MKF[136 + winner_character]`。成交者第三套人物资源以
   100 ms 节拍循环，最多 60 tick。未成交播放 `Speaking.MKF[148]`。

动作数值与原私有消息 `0x407` 的 `wParam` 完全一致：

| 值 | 动作 | 金额 |
|---:|---|---:|
| 0 | PASS | 0 |
| 1 | 加价 | 100 |
| 2 | 加价 | 500 |
| 3 | 加价 | 1000 |
| 4 | 加价 | 5000 |
| 5 | 加价 | 10000 |
| 6 | Give Up | 0 |

每次加价要求 `current_price + amount <= bidder.cash`。成交结算从买家现金扣款；
seller 为 -1 时进入系统资金，否则转入卖方账户；随后写入新所有者。SDL 将调用
方的“卡片未成交清主”政策显式放在请求 flags 中，避免把不同入口错误合并。
点击超过现金上限的加价仍播放动作音，但不改变竞价状态；若轮到某人时当前价已
严格大于其现金，原回调不开放按钮而是自动执行 Give Up。

## AI 决策

`0x439F0D` 在开拍时为每个 AI 固定计算一次最高价：

```text
random       = rand / 32767 * 0.3 + 0.5
scarcity      = 6 - 4 * unowned_count / total_count
land factor  = 同名已持有土地数 + level/2 + 1
facility factor = level/2 + 1
estimate     = price_index * current_price * factor * scarcity * random
cap          = price_index * base_price * (3 + rand/65536)
ceiling      = min(estimate, cap, AI cash)
```

AI 选择最高价支持的最大按钮档位。已有领先者时，还会以
`leader_cash + 500 - current_price` 为阈值向下收敛档位；阈值不超过 5000 时才
应用这条限制。无法加 100 时 PASS；当前价已高于现金时 Give Up。

## `Panel.MKF[26]` 布局与图块

| 内容 | chunk / 资源 | 原锚点或热区 |
|---|---|---|
| 全屏底图 | chunk 0 | `(0,0)` |
| 标题装饰 | chunk 25 | `(123,24)` |
| 成交报幕标题 | chunk 21 | `(124,27)`，`Speaking[135]` 期间 |
| 标的框 | chunk 17 | `(67,63)` |
| 标的图片 | 下表动态 chunk | `(232,180)` |
| 标的名称 | 地图记录固定宽度 Big5 名称 | `(182,242)` |
| 当前价 | 十进制文本 | `(272,262)` |
| 玩家行 | `Panel[27 + 3*character]` 起的三资源组 | `(590,80+120*row)` |
| 当前竞价者标记 | chunk `78+character` | 同玩家行锚点 |
| 7 个按钮 normal | chunks `4,6,8,10,12,14,16` | 中心 `(406,133+48*n)` |
| 7 个按钮 pressed | chunks `3,5,7,9,11,13,15` | 同上 |
| 动作反馈气泡 | chunk 1 + 文本 | `(480, 玩家行-15)`，持续至第 10 tick 前 |

按钮命中范围为包含边界的 `x=363..449`，每项 y 中心上下各 19 px。鼠标移动
不会切换图块或播放选择音；左键按下显示 pressed 图块，抬起恢复 normal 并提交
按下时记录的动作。
人物三资源组分别是正常/竞价反馈、排除状态、成交庆祝；排除文字来自
`0x464EA8..0x464ED2`：“住宿中、消失中、坐牢中、住院中、冬眠中、梦游中、卖方”。
正常竞价者开场显示其现金；第一次成为领先者后，该行改显当前价，旧领先者的
金额区清空。拍卖师的随机表情还会复用 Panel 26：上部序列为 chunks
`26,27,26`，下部序列为 `18,19,18`；普通报幕嘴型使用 chunks `28/29`，
成交报幕嘴型使用 chunks `22/23`。这些微表情不参与规则或计时状态转移。

### 标的图片 chunk 公式

土地：

- 0 级：无主为 90；有主为 `91 + owner_character`。
- 场景 0：普通土地为 `level + 5*map + 29`；连锁/特殊土地为 50。
- 场景 1：普通土地为 `level + 5*map + 115`；特殊土地为 `map + 131`。

设施：

- 0 级：无主为 103；有主为 `104 + owner_character`。
- 场景 0：type 0 为 51；其余为 `level + 5*(type-1) + 51`。
- 场景 1 type 0：map 0 为 151，其余为 51。
- 场景 1 type 1/2/4：以表 `{134,167,151,51}[map]` 为基数，type 4
  映射到 slot 2，再加 `5*slot + level`。
- 场景 1 type 3：表 `{150,183,167,62}[map]`。

## 音乐与资源清单

| 类型 | 资源 | 用途 |
|---|---|---|
| UI/人物/标的 | `Panel.MKF[26..62]` | 主面板、动态标的图、12 名角色三资源组 |
| 语音 | `Speaking.MKF[131]` | 开场 |
| 语音 | `Speaking.MKF[132]` | 底价 |
| 语音 | `Speaking.MKF[135]` | 成交价 |
| 语音 | `Speaking.MKF[136..147]` | 12 名角色的获胜台词 |
| 语音 | `Speaking.MKF[148]` | 未成交 |
| 音效 | `Effect.MKF[63]` | PASS、加价、Give Up 的动作反馈 |
| 音效 | `Effect.MKF[29]` | 成交落槌 |
| 音乐 | 固定音乐索引 5 | `MIDI06.MID`，运行时 track 15 |

普通入口在模态期间切到音乐索引 5，退出后恢复地图播放列表。原破产函数在三次
共享拍卖外层只切换一次；SDL 将三个连续请求都标为管理拍卖音乐，模态音乐状态
跨队列保持活动，只在整个队列结束后恢复，听感与生命周期等价。

## SDL 分层实现

- `core/auction.c`：底价、资格、轮转、PASS/Give Up、AI 上限、结算。
- `app/auction_flow.c`：事件排队、语音阶段、100 ms 动画节拍、真人/AI 调度。
- `platform/sdl1/game_auction_render.c`：Panel 26、标的公式、Big5 名称、人物状态、
  精确按钮坐标、按下态、动作反馈气泡、成交标题和逐帧人物资源。
- `core/card.c`、`core/special_event_commit.c`、`core/special_event_magic.c`、
  `core/ledger.c`：四类入口只发 typed auction request，不再提前伪结算。
- `platform/sdl1/game_loop_modal_music.c` 与 SDL audio：固定拍卖音乐、两项 Effect
  资源和 Speaking 队列；拍卖期间吞掉取消键与右键，不存在退出捷径。
- 单元测试覆盖底价/资格、PASS 重置、单人竞价、AI 档位、所有权与资金结算、
  四类请求策略、破产三标的无放回选择、精确 hitbox 和完整语音阶段链。

## 首轮新闻拍卖及 SDL 修正（2026-10-12 IDA 复核）

- `0x448B81` 开局排列全部 36 个新闻。`0x448BE2(7)` 仅要求存在无主
  普通地产或设施；`0x449735` 从这些地块中随机选择，调用
  `0x43BDE5(-1, target, 1)`，无首轮、落地人数或建筑等级限制。
- `0x4072E4` 复制的角色模板中 who_plays（+0x15）为 0；`0x4072F9`
  把控制类型先存入 +0x64。入场时 `0x418D07` 才写入 who_plays。
  拍卖在 `0x43C11F` 直接跳过 who_plays 为 0 的玩家。
- SDL 提前保留 play_state 供回合系统使用，拍卖入口因此用已有的
  first_turn_landing_pending 构造资格快照：未落地者视作 who_plays 为 0。
  不改变全局状态，不为未落地 AI 消耗估价 RNG，绘制时也不为其占行。
- 原版 `0x43B093` 在人类可出价时开启光标，`0x43B0E7` 在 AI 出价时
  关闭；SDL 拍卖输入须优先于被暂停的回合/入场流程。
- `0x43C287/0x43C2B4/0x43C2E1` 从 Panel.MKF 加载
  `27 + 3*character + pose`。`0x45663E` 使用索引色调色板、索引 0
  透明及 anchor 减 hotspot；人物须走 SPR 路径，而非 SMP 直接像素路径。

回归测试覆盖首条新闻拍卖无主普通地/设施、未落地排除、落地后加入、
RNG 保持以及光标输入。`test-auction-presentation` 用原版 Panel.MKF
验证 12 名角色的 3 类姿态共 36 组资源像素及未落地人物不占行。
