# 整局随机流与 AI 像素候选表

核验日期：2026-10-13。原版 `Rich4.exe` SHA256：`5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`。IDA 基址 `0x400000`。原始反编译、随机调用交叉引用、汇编和坐标计算见 [IDA 证据](../../../rich4/docs/evidence/ai_rng_pixel_compatibility_ida.json)。

## 随机状态、播种与消耗顺序

`0x456F23` 通过 `0x4585CD` 取得运行库线程数据，加 `0x0c` 定位随机状态。主线程上的游戏、AI、股票和表现调用共享这个 32 位字。`0x456F2D` 的算法是无符号回绕的 `state = state * 1103515245 + 12345`，返回 `(state >> 16) & 0x7fff`；`0x456F50` 写同一状态。种子 0 是有效值，其第一次更新为 12345、第一次返回 0。

| 阶段 | 原版地址和顺序 | SDL 对应 |
|---|---|---|
| 程序启动 | `0x401707 → 0x40170F`，`GetTickCount → srand` | `runtime_main.c`；Windows 交互运行使用 `GetTickCount`，smoke 使用固定种子 |
| 新局排列 | `0x406DE7 → 0x448B81 → 0x44BAEA`，新闻排列先于命运排列 | `new_game_init.c`、`special_event.c`，同一个 Watcom 状态 |
| 地图初始化 | `0x407AD2`：八个动态对象放置 → `0x42915A` 股票成交量 → `0x40829D` 人物起点/首边 | `game_session_runtime_init.c`；平台新局配置延后成交量初始化 |
| 落地介绍结束 | `0x402F99 → 0x402FA1` 再次按 `GetTickCount` 播种 | `intro_flow.c`；自然结束与跳过共用 `finish_at_tick` |
| 每天更新 | `0x41CF67`：先 `0x41D89E` 检查结束条件，再倒计时；`0x41D066 → 0x41D06E` 播种 → `0x4291D6` 股票 → 15 日结算/跨月银行及礼物、宝箱放置 | `turn_rotation.c` 的 `advance_once_events_at_tick`，app 传入原版时钟值；结束当天跳过播种和股票 |
| 时光机 | `0x447387 → 0x448544` 恢复游戏数组，未恢复运行库线程随机字 | `game_command_flow.c` 保留使用前的实时随机字 |

每天重播种发生在股票更新前，**不限定跨月或交易日**。`0x42915A` 本身只初始化成交量，不调用每日股票函数。原版的定时表现也参与随机消耗，因此单独相同的开局种子不能保证逐帧轨迹相同。

SDL 活动游戏唯一随机字为 `GameState.ai_rng_state`；字段名保留以保持存档布局。原 `stock_rng_state`、`special_event_rng_state` 仅为旧存档保留字段，没有活动消费者。事务中的 `Rich4Rng` 是该字的临时副本，接受事务后提交。挂牌命令回调前提交、回调后重新读取，避免覆盖回调已经消耗的随机数。

AI、骰子/路径分岔、股票、银行/拍卖、卡片/道具、新闻/命运、特殊人物、神明与动态对象、人物发言、银行/商店待机和小游戏表现均从该字继续消费。菜单的进程状态在新局时导入；返回菜单时导出活动局状态。无 session 的独立兼容 API 仍使用进程状态，平台活动游戏入口使用带状态参数的 API。

时钟桥 `GameSession.rng_clock_offset` 为暂态，映射渲染时钟到原版 `GetTickCount`。core 不自行读取墙钟；无 tick 的纯 core API 可用于确定性回放。SDL 自身存档保存统一随机字，旧存档可以读取；旧版分流存档后续不能延续原先三条独立流的轨迹。

## 完整候选来源

全局表来源为 `0x40829D` 生成的绘制队列，`0x48A84C` 每项 12 字节：资源指针 `+0`、raw ID `+4`、投影锚点 X/Y `+8/+10`。`0x48A44C` 的排序项高字给出队列索引。`0x409DE7` 清空 440×440×2 字节，再检查非空资源、非零 raw 和动态附着状态；在 `(X,Y-40)` 处按位 OR。它使用单个锚点，**不按 SPR 的可见像素或鼠标命中轮廓决定 AI 候选**。

| 来源 | raw 编号 | 准入/排除条件 |
|---|---|---|
| 普通人物 | `0x8000 | (1 << player)` | world X 非零；`+50..+53` 清零或 `+21` 的 `0x20` 位允许绘制；当前主资源存在 |
| 四名特殊人物 | `0x8000 | (0x10 << slot)` | 当前特殊人物记录可见且主资源存在；非这四槽的附加绘制项 raw 为零 |
| 人物覆盖层 | 0 | `0x4088D5`、`0x408AF5` 后续覆盖层条目，raw 零不入表 |
| 动态池的地面神明、NPC、工具 | `0x8000 | ((slot + 1) << 8)` | 对应资源存在；高字节低六位给出池槽；`attached_player == 0` |
| 附着神明/炸弹 | 动态槽 raw，炸弹绘制还可带 `0x4000` | `0x409DE7` 按槽的附着 byte 排除 |
| 飞行动态对象 | 0 | `0x408DD6` 写 raw 零，不入表 |
| 住宅 | `2000 + one_based_index` | level>0 的住宅/覆盖建筑资源，或有主 level=0 的所有者标记；无主 level=0 资源为 NULL |
| 设施 | `4000 + one_based_index` | 按类型/等级取资源；有主 level=0 使用所有者标记；无主 level=0 不入表 |
| 公司辅助对象 | `6000 + one_based_index` | `+32` 的 sprite 索引非零，对应资源存在 |
| 特殊地点/静态对象 | `8000 + one_based_index` | `+26` 的 sprite 索引非零，对应资源存在 |
| 道路底图与 raw=0 装饰 | 0/独立底图绘制 | 不贡献全局 raw 候选；空道路使用独立道路表 |

SDL 对应 `render/game_map_info.c:game_map_collect_ai_objects`，实际 AI 和请神候选共用入口。它从当前 session 的人物、住宅和设施重建条目，公司/特殊地点从地图资源条目取得；资源存在与 SDL 解码成功分开判断。UI 的空地命中遮罩不进入 AI 表。29×29 窗口内、但锚点不在 `X=0..439,Y=40..479` 的条目也排除。core 压平时同点 raw OR、按 Y/X 排序，不对重复编号去重。

## 三种表的不同语义

| 建表函数 | 来源 | 同点处理 | 扫描范围 |
|---|---|---|---|
| `0x409DE7 → 0x40A45C` | 上述全部资源有效绘制条目的锚点 | 按位 OR | r=-1：440×440；其他 r：从 `(220-r,220-r)` 起扫描 `2r×2r`，按行压平非零 |
| `0x409EF9` | 一基道路；route `+36 & 0x00ffff00 == 0` | 后编号覆盖前编号 | 440×440，按行压平 |
| `0x40A0B1` | 当前 AI 自身人物（四个状态 byte 全清），再有主住宅，再有主设施；不检查建筑资源是否存在 | 后写覆盖前写，设施能覆盖住宅/人物 | r=100：中央200×200；r=-1：440×440 |

这些表不共享鼠标 hit mask。`0x409B18` 是恢复/建立鼠标命中表的另一入口，使用道路及资产公共遮罩和资源轮廓，不能作为 AI 像素表的来源规则。

投影统一遵循 `0x407A2C`：每个 X/Y 子格乘积分别算术右移 5 位，然后相加；不能把两个乘积相加后再统一右移。29×29 网格来自 `0x46CCF0`，每格依次存 `{Y,X}`。八方向共 **6728 格、13456 个 signed word、26912 字节**，已逐值与 IDA 比较完全相同；字节 SHA256 为 `d8587a20948b0c53fb67d0632c65b64e1f46e186bc3e93568d448e5bbd9e7a09`。系数来自 `0x474910`；方向1首项为 **-34**。

## 验证与边界

- `test_rng`：原版序列、种子0、显式状态及局部副本混合消费。
- `test_ai_flow`：股票 → 汽车预看骰数 → 卡/工具入口连续消耗；不改变菜单状态。
- `test_game_session_runtime_init`：原版前八次抽取的动态落点和紧随其后的十二次股票成交量，最终随机字一致。
- `test_turn_rotation`：同月连续两天都重播种；种子0有效；达到结束日期的当天不播种、不推进随机字。
- `test_tool_prompts_sdl`：真正时光机命令恢复库存/流程时保留实时随机字。
- `test_ai_pixel_candidates`：八方向所有类别条目、资源存在但未解码、空资源、覆盖层/附着/飞行排除、窗口内像素外裁剪；逐个比较整个 193600-word 表。
- `test_ai`：全局同点 OR、道路后写覆盖、局部资产/自身覆盖、范围及候选策略。真实地图、整局和存读档回放另行执行。

这些验证确认共享状态所有权、已接入入口、静态投影数据和候选建表规则；没有原版与 SDL 同一时钟输入的长期逐帧轨迹、全部地图动态场景和完整动画像素录制对照。纯 core 人工状态未提供完整对象表时仍有 typed 回退，不能宣称与原版视口表等价。SDL 开局历史报价快照的时点不在此次随机/候选表验证结论内。

执行命令为 `python scripts/make_minimal.py BUILD_DIR=build/ai-compat-clean BIN_DIR=bin/ai-compat-clean test-unit test-replay test-ai-pixel-candidates test-tool-prompts-sdl test-render sdl --progress`；隔离目录从空目录构建。上述目标均通过，`git diff --check` 按 CRLF 行尾检查通过。

真实 SDL runtime 使用 dummy 视频/音频，在独立工作目录复制配置后各运行两次：菜单2帧的 framebuffer/sequence 为 `21f26f63 / f8719841`，游戏120帧为 `03ce8e1f / 021f4318`；两次完全一致，并与现有 smoke 基线相同。

独立专项 `test-stock test-special-event test-special-place-alignment` 通过；探监/探病通知测试明确使用原版奇数随机值通过入口，再分别验证点券30/31的支付门槛。

停留卡 handler `0x443F80` 对 raw=0 取消；非零旧 raw 的低字节为0时，`0x40D293` 返回-1，可能产生越界目标。八个人物位同时包括普通及特殊人物，不能只检查四名普通人物。SDL 对无效目标拒绝。运行期 `0x48BE58` scratch 未存入现有 SDL 存档。

新闻15仅有已建设施时 `0x44A453` 的零住宅候选除零是已知原版 BUG。按用户指定，SDL 资格判断及候选均只计已建住宅，没有住宅时继续扫描下一条新闻；具体记录和回归见 [特殊事件证据](m3-8-special-events.md)。上述异常路径及明确的 SDL 例外不具有字节级行为等价性。

原版读档恢复新闻/命运排列和游标后，在 `0x402F99/0x402FA1` 以当前 `GetTickCount()` 调用 `srand`。运行时加载入口采用当前进程时钟重新播种；存档解码保留序列化随机状态，供回放和检查使用。`0x448544` 时光机仍只恢复游戏数据，保留使用时的实时随机字。
