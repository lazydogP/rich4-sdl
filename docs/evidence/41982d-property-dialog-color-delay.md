# 原版角色代表色、地产询问框与购买后回合延迟

本文记录 Rich4 V3.11 在角色代表色、普通地产购买询问框和购买成功后的回合收尾行为，并给出 SDL 实现约束。结论来自 `rich4/asm`、`rich4/csrc` 与 V3.11 原始资源交叉验证。

## 1. 角色代表色是 `0x00RRGGBB`

角色模板见 `rich4/asm/players.c`。此前 SDL 将字段误当作 Win32 `COLORREF`（`0x00BBGGRR`），导致红、蓝通道互换。`sub_409866..0x40987D` 读取角色颜色后调用 `sub_4551F0`；标准 RGB565 分支 `sub_45525C` 从输入高字节提取红色、低字节提取蓝色，证明逻辑输入格式是 `0x00RRGGBB`。`set_pixel_fmt` 选择 BGR 转换器只是在适配特殊显示表面，不改变角色字段的逻辑格式。

| 角色 | 原始常量/逻辑 RGB888 | 标准 RGB565 截断后的截图 RGB |
|---|---:|---:|
| 约翰乔 | `0x00946126` / `#946126` | `#906024` |
| 沙隆巴斯 | `0x00BDC3C6` / `#BDC3C6` | `#B8C0C0` |
| 忍太郎 | `0x0041323B` / `#41323B` | `#403038` |
| 钱夫人 | `0x00C626C3` / `#C626C3` | `#C024C0` |
| 阿土伯 | `0x00C5B830` / `#C5B830` | `#C0B830` |
| 莎拉公主 | `0x00ED9D9D` / `#ED9D9D` | `#E89C98` |
| 宫本宝藏 | `0x0000F038` / `#00F038` | `#00F038` |
| 糖糖 | `0x00FFFFA0` / `#FFFFA0` | `#F8FCA0` |
| 乌咪 | `0x00E77C08` / `#E77C08` | `#E07C08` |
| 孙小美 | `0x00CC1A20` / `#CC1A20` | `#C81820` |
| 小丹尼 | `0x002017FE` / `#2017FE` | `#2014F8` |
| 金贝贝 | `0x000EBDBD` / `#0EBDBD` | `#08BCB8` |

SDL 的 SPR 合成器内部仍使用资源侧 RGB555；实现必须先按 `RRGGBB` 提取通道，再量化为 RGB555。右上 HUD 色条等直接屏幕填充则按 `sub_45525C` 量化为 RGB565。表中截图值采用原版截断式读回，即 `(R & 0xF8, G & 0xFC, B & 0xF8)`。

## 2. 通用询问框来自 `Data.MKF[517]`

`rich4/csrc/loadsave.c` 对应的原版加载为：

```c
data_0205 = read_mkf(mkf_data, 0x205, NULL, NULL);
```

因此 V3.11 应读取 `Data.MKF` 的零基条目 `0x205`（十进制 517），而不是把 `Panel.MKF` 或 `Data.MKF[440]` 当作通用背景。

| 用途 | 资源与零基 chunk | 原版证据 |
|---|---|---|
| 通用询问/购买询问背景 | `Data.MKF[517].chunk[5]` | `sub_440BA8` 的资源偏移 `+0x48`；锚点 `(220,140)` |
| 角色发言窗口背景 | `Data.MKF[517].chunk[6]` | `player_say/sub_44EF41` 的资源偏移 `+0x54`；锚点 `(220,130)` |
| 是/否控制图形 | `Data.MKF[440]` | `sub_453A32`；与背景是两个独立资源 |

图块表从资源结构 `+0x0C` 开始，每项 12 字节，所以 `+0x48` 对应 chunk 5，`+0x54` 对应 chunk 6。SDL 绘制购买询问时必须先以 hotspot 语义将 chunk 5 锚定在 `(220,140)`，再绘制地产名称、金额和问题文字，最后绘制 `Data.MKF[440]` 的确认控制。

## 3. 购买后等待 8 个逻辑 tick，再切换玩家

购买成功分支位于 `sub_41982D`。成功后写入所有者、刷新画面、异步播放 `Effect.MKF[49]`、扣款并执行公共地产收尾。`sub_4542CE -> sub_4540D8` 只调用 DirectSound 的定位、播放和音量接口，不查询播放完成状态，因此回合延迟不是等待音效结束。

普通地产公共尾部在 `0x41B111` 将返回状态改为 `0x88`：

```text
0x88 = 0x80（倒计时结束后结束回合） | 8（剩余逻辑 tick）
```

`sub_418E7F` 将该值写入当前玩家行动状态；`sub_40D7C4` 每个逻辑 tick 递减低 7 位，完成 8 次递减后才允许 `sub_418EBD` 轮换玩家。该倒计时属于地产事件公共收尾，不是角色专属延迟。

原版基础定时器由 `timeSetEvent(20,5,...)` 驱动，正常可选速度的逻辑 tick 为：

| 游戏速度 | 每 tick | 8 tick 标称等待 |
|---|---:|---:|
| 最慢 | 120 ms | 960 ms |
| 中速 | 80 ms | 640 ms |
| 最快 | 40 ms | 320 ms |

购买音效可以与该倒计时并行播放。若购买后满足同名地产发言等额外条件，`player_say` 的语音/窗口等待会在公共倒计时之外增加可见停顿，不能用“等待购买音效结束”模拟。

## 4. 无主普通地产的购买询问

`sub_41982D` 的无主分支从 `0x41A013` 开始。角色不在冬眠、没有阻止购买的神明且现金足够时：

- 真人 `play_state == 1` 调 `sub_440BA8` 显示是/否框；在选择前路线事件和回合轮换均暂停。
- AI 不显示可操作按钮，按原版保留资金规则直接决定是否购买。
- 原版购买分支使用 `0x4639E1`，正文格式为：地产名、空行、`费用:%d元`、空行、`是否买下此地？`。`sub_440BA8` 将整段文字以锚点 4 一次绘制在 `(220,140)`，字体高度 16、粗体，逻辑前景色 `#F0F0F0`、一像素阴影色 `#101010`。
- 背景为 `Data.MKF[517].chunk[5]`，确认控制另取 `Data.MKF[440]`。
- 成功顺序为：写 owner、刷新地图、异步播放 `Effect.MKF[49]`、扣现金、检查同名地产数量、进入地产公共收尾；拒绝不会播放购买音效也不会扣款。

## 5. 购买后的额外发言与真实延时来源

购买成功会调用 `sub_44F627(property_name, 0)`。它遍历全部普通地产，以**名称字节完全相同**为组，统计当前玩家拥有的数量：

- 少于 3 块：不发言。
- 第 3 块及以后：必定调用 `player_say(current, 0, character_table[16])`。
- 另一个 `mode != 0` 调用形式使用 table[17] 且只有 `1/3` 概率发言；普通购买传入的是 0，不走随机分支。

顺序是“购买音效开始 → 条件性对白及语音等待 → 设置 `0x88` 公共回合尾状态”。因此总停顿由两段串联组成：

1. 若有对白，至少 1000ms，并继续等 `Speaking.MKF` 语音结束；
2. 随后才执行 8 个逻辑 tick（320/640/960ms，取决于速度）。

购买音效本身不被等待。没有对白时只剩 8 tick；有对白时不能让 8 tick 与语音并行倒数。

## 6. `player_say` 的通用窗口与语音协议

`player_say/sub_44EF41` 的行为是：

1. 用静态指针记录上一次字符串；本次若是同一个字符串指针，直接返回，不画窗口、不播语音。
2. 玩家索引高位 `0x8000` 用于禁止发言前的镜头定位；正常调用在状态检查通过后，以发言者的当前世界坐标调用 `0x41D476`，再显示对白。
3. 发言者的 `days_disappearing`、`days_sleep_walking` 或 `days_sleeping` 任一非零，整段发言被抑制。
4. 画 `Data.MKF[517].chunk[6]`，锚点 `(220,130)`。
5. 画发言者 `Map.MKF[27 + character].chunk[speech_type + 1]` 肖像，锚点 `(170,130)`。
6. 字符串以 `#NNNN` 开头时，`NNNN` 是 `Speaking.MKF` 的零基资源号；显示时跳过 5 字节前缀并播放该资源。
7. 跳过 `#NNNN` 后若正文为 `@NN`，不画文字，改画 `Data.MKF[519].chunk[NN-1]`，锚点 `(240,130)`；金贝贝的对白使用此分支。
8. 否则在 `(200,130)` 一带绘制 Big5 正文。
9. 无语音或语音关闭时保证窗口至少 1000ms；有语音时等语音结束。鼠标/键盘抬起可提前中断。

`0x41D4DA` 比较目标坐标和当前行动者坐标；相等时清除观察标志
`0x48BE18`，否则保存目标坐标并置观察标志。`0x416E6D` 的白框始终标记
当前行动者；红框标记观察位置，仅在两框的小地图坐标不同时显示。
对白不改变行动者，也不修改地图旋转方向。

过路费收款链 `0x419FF0 → 0x44F354 → 0x44EF41` 会定位收款人；
新闻房屋受灾先在 `0x44A52E` 定位地产，随后 `0x44A5C3` 的对白定位业主。
神明到来的五类对白 `0x40EF44/0x40F00D/0x40F0AC/0x40F17E/0x40F314`
均传入 `player | 0x8000`，保持已有视角。

手动托管保留真人身份并设置玩家 `+21` 的 bit 2，控制状态为 5。
重新进入 `0x418C55` 时，`0x418D69 → 0x41D546` 先清观察标志并重新居中，
再执行状态检查和 AI 的股票、卡片或道具预行动。道具入口 `0x447D97`
只有控制状态恰为 1 的真人面板分支执行其自身的 `0x41D546`；托管分支
依靠上述回合入口以及正常道具对白的定位。

## 7. 停在他人普通地产：完整先后顺序

他人地产分支从约 `0x419A67` 开始。通过 `sub_41D559` 的免付/保护检查后，原版顺序为：

1. 进入分支立即异步播放 `Effect.MKF[55]`，不等待音效结束。
2. 计算同名普通地产合计租金；当前 owner 有关联收款人时，原版还会把符合条件的关联 owner 同名地产纳入。
3. 生成 440×440 对象 ID mask，找出所有实际参与本次同名合计的地产。
4. **匹配数量大于 1 才闪烁**；只有一块时不调用闪烁函数。
5. 显示金额框 1500ms。
6. 依次判断并播放付款方对白、收款方对白。
7. 对白全部结束后才调用付款/破产事务。

### 闪烁

`0x41982D` 的范围选择区分普通住宅和连锁店：普通住宅只匹配同名、
`type==0` 且屋主为当前收款人或其关联收款人的地产；连锁店匹配这两位
收款人的全部 `type!=0` 地产，不限制街名。未建地块也参与数量统计。
只有匹配数量大于一才进入闪烁，设施和公司不进入这一分支。

`sub_451985` 只修改 mask 中对象 ID 被标成 `0xFFFF` 的地产像素。16 帧亮度偏移依次为：

```text
+4,+8,+12,+16,+12,+8,+4,0,-4,-8,-12,-16,-12,-8,-4,0
```

每帧 30ms，末尾再保持 400ms，标称总时长约 880ms。角色或其他遮挡对象不属于地产 mask，不随地产一起变亮/变暗。

`0x451985` 在循环外复用对象掩码和不变的地图源图。循环逐次读取亮度表，
等待垂直空白、合成并解锁画面后，才调用 `0x4528B9(30)`；输入可中断该
循环，但仍保持最后画出的亮度帧，进入独立的 `0x4528B9(400)`。
绘制耗时不会使循环跳过后续亮度帧。

`0x409B18(1)` 的掩码覆盖地产底面与建筑的非透明像素，并遵循统一队列
遮挡顺序。底面资源是 `Map.mkf[26]`：住宅 chunk 为旋转结果最低位，
设施 chunk 为该位加二。`0x4554FC` 从最终地图画面取色，通过
`0x485D68` 的亮度查表生成每帧，未命中地产掩码的像素保持原样。

### 金额框

金额框使用通用定时消息 `sub_440CAC(message, 1500)` 与 `Data.MKF[517].chunk[5]`。普通单 owner 文案为：

```text
地产名

此地属<owner>

请付<amount>元
```

有关联收款人时为“属 A 与 B”。展示的是保护、同名合计及价格指数处理后的应付金额；原版在金额框和对白结束前尚未转账。

### 付款方发言条件

先调用 `sub_44F4ED` 尝试特殊关系台词：

- 从仍在游戏的其他玩家中，选择付款方 `relation_balance[]` 最大者；
- 该玩家必须正好是本次 owner；
- 金额 `>= 5000 * price_index`；
- `rand() & 1` 为 1（50%）。

满足时使用 speech type 1、表项 18，并跳过普通付款台词。否则调用 `sub_44F42D`，使用 speech type 2：

- `>= 9000 * price_index`：固定高1；
- `>= 5000 * price_index`：高1/高2随机；
- `0 < amount < 5000 * price_index`：固定低；
- 金额为 0：不发言。

这里与收款方并不对称：`sub_44F42D` 在低档分支只执行 `test amount, amount / jle`，没有 2000 门槛。此前 SDL 错误复用了收款方门槛，导致 1..1999 档的付款人不发言。

### 收款方发言条件

随后无论付款方是否说话，均调用 `sub_44F354` 检查 owner，使用 speech type 3：

- `>= 9000 * price_index`：固定高1；
- `>= 5000 * price_index`：高1/高2随机；
- `>= 2000 * price_index`：固定低；
- 更低：不发言。

双方仍受 `player_say` 的消失、梦游、冬眠抑制和相同指针去重约束；被抑制不会取消付款。

## 8. 大地图对象与当前回合角色的显示优先级

`sub_40829D` 把需要遮挡的角色、地产、设施、特殊表对象和动态对象放进同一队列。普通 key 的低 16 位为有符号 `screen_y * 16 + type_bias`，按低 16 位升序绘制；越靠屏幕下方越晚画，因而遮住上方对象。比较器相等时返回 0，原版 qsort 不稳定，不能依赖插入顺序作平手规则。

与“当前轮到谁”直接相关的 bias 是：

| 对象 | 当前实体 | 非当前实体 |
|---|---:|---:|
| 普通玩家主体 | `0x0D` | `0x0C` |
| 普通玩家可选 overlay | `0x0F` | `0x0E` |
| 特殊玩家主体 | `0x0D` | 通常 `0x08` |

所以同一 `screen_y` 附近，当前玩家主体比其他普通玩家晚一个 bias 绘制；当前玩家 overlay 也相应晚一个 bias。这个“当前角色优先”只解决近似同深度冲突，不会让当前角色无条件浮在所有建筑之上：建筑/地产仍按自身 `screen_y` 参与统一遮挡。

例外层：道路节点标记和地产/设施 parity overlay 在收集阶段立即绘制，不进统一排序；自由飞行动态对象使用固定低 word `0x7FF0`；落地 FLC 属独立的后续合成路径。更完整的表字段与特殊玩家分支见 [0x40829D 地图绘制记录](40829d-map-render.md)。

## 10. 升级确认框、升级收尾与初始朝向补证

### 所有 `sub_440BA8` 地产确认框

`sub_41982D` 中的四个调用点分别覆盖普通地产升级（约 `0x41994D`）、普通地产购买（约 `0x41A098`）、大型建筑升级（约 `0x41A31F`）和大型建筑购买（约 `0x41A8D9`）。它们都把一段已经格式化好的五行字符串交给同一个 `sub_440BA8`：

- 购买使用 `ref_4639E1`：`%s\n\n费用:%d元\n\n是否买下此地？`；
- 升级使用 `ref_46396D`：`%s\n\n升级费用:%d元\n\n是否升级？`；
- 两者都以 `(220,140)`、anchor 4 一次绘制，使用 16px、前景 `#F0F0F0`、阴影 `#101010`、style 3；
- 两者都在其后调用 `sub_453A32(220,320)`，因此普通地产和大型建筑的 YES/NO 默认及 hover 图块完全相同。

SDL 不再把升级内容拆成三个深色单行；购买文案也不再误带“升级费用”。

### 升级后是否有与购买相同的延迟

有。购买和升级分支的局部动作并不相同：购买会写 owner、播放 `Effect.MKF[49]` 并调用 `sub_40A4E1(0)` 重建地产显示；升级会增加 level、播放升级音效，普通地产非满级时还可能调用 `sub_44F627(name,1)`。但这些差异都不是 8 tick 的来源。

所有这些分支最终都汇合到 `0x41B077`，并在 `0x41B111` 无条件把返回行动状态写成 `0x88`。因此升级与购买一样，在它自己的同步对白（若有）结束后，再执行低 7 位的 8 tick 公共地产收尾；不等待购买或升级音效播放完毕，也不是角色自己的回合结束延迟。

### 落地后朝向和第一次行走朝向

新游戏放置路径位于 `0x40829D`：

1. `sub_40AA0F` 选出未占用的起始 route node，写玩家 `+12`；
2. 扫描该 node 的 `next[0..3]`（route record `+0x18..+0x1E`），收集所有非零邻接点；
3. 用 `rand() % count` 随机选一个，写玩家 `+14`；
4. 调用 `sub_407A8C(next,current)`，再把结果写玩家方向字节 `+16`。

`sub_407A8C(a,b)` 取的是 `b.xy - a.xy`，再交给 `sub_454FB4` 和方向表 `{2,3,4,5,6,7,0,1}`。首次落地时 `+12` 仍是当前节点、`+14` 是预选邻接点，所以该初始化调用得到 `current-next`；这只是落地初始朝向的参数语义。

第一次掷骰开始移动时，玩家 `+14` 中这个预选邻接点仍是第一条边，不能重新随机首边。但 `sub_40C05C` 在开始插值前会把旧 `+12` 写到 `+14`，再把选中的目标写到 `+12`。因此 `0x40C410` 的 `sub_407A8C(+14,+12)` 实际得到 `target-old`，与插值使用同一正向位移。SDL 保留预选 `next_node`，首步直接使用它，行走动画则按 `move_to-move_from` 映射方向；不得反向。

## 11. 2026-07-18 回归补正：收费颜色、确认 hover、闪烁与银行格

### 收费框颜色

`0x419D50` 把已经格式化好的整段收费文字交给 `0x440CAC`。后者在
`0x440D06` 调用 `rich4_create_font(16, 0xF0F0F0, 0x101010, 3, 1)`，再以
anchor 4 一次绘制整段；因此收费文字不是此前 SDL 使用的深色 18px 三行字。
SDL 已改回 16px 浅色前景、深色一像素阴影和单次多行绘制。

### YES/NO hover

`0x453A32` 读取 `Data.MKF[440]`，该 SMP 正好有三个 chunk。其窗口过程
`0x45367E` 在 `WM_MOUSEMOVE` 中按按钮总宽度的一半计算 `hover + 1`：无
hover 绘制 chunk 0，YES 绘制 chunk 1，NO 绘制 chunk 2；进入新的有效半区
还播放选择音效。SDL 现在逐帧命中同一左右半区并使用相同 chunk 映射。

### 未建房 owner 标志的闪烁

同名地产 mask 和 16 帧序列原先已经接入，但 SDL 的 SPR 包装器在
`palette_owner == 0xFF` 时直接转入“不调色”绘制。普通地产 level 0 正好使用
这个 owner 标志路径，所以实际画面看不到闪烁。现在该路径只关闭 palette
index `0xFF` 的 owner 替换，仍对所有非透明地产像素应用亮度偏移；建房地产
继续同时执行 owner 换色和闪烁。

### 银行格不是显示对象 ID 分支

原版 `0x41982D` 从路线记录 `+0x20` 读取显示对象 ID，但真正的地点动作由
`+0x24` 低字节的 0..16 跳转表决定。动作 14 进入
`0x41B396 -> 0x4379C9`（银行）。八张原始地图中，银行动作 14 搭配的显示对象
可为 `0x1772`、`0x1773`、`0x1776`、`0x177B` 等，不能把 `0x1772/0x1773`
硬解释成新闻/命运；这正是 SDL 此前银行格误触发其他事件的原因。

SDL 的 `RouteEventSnapshot` 现已保存 `flags & 0xFF`。真人动作 14 会冻结路线
执行器并打开 `Panel.MKF[24]`；面板命中矩形直接取自 `0x475888`，支持取款、
存款、数字键、C、退格、MAX、原版分段滑杆公式、确认与退出。交易完成后才
恢复路线执行。`days_rejected_by_bank` 会拒绝进入面板，
`days_bank_no_loans` 会禁止取款侧并从存款侧开始。AI 在银行的概率与现金比例
重分配分支现已接入 `rich4_bank_run_ai_transfer`：目标现金比例按原版钳制到
10%..90%，月初 1..7 日乘 1.5、月末 26..31 日乘 0.5，只有现金比例偏差达到
含边界的 ±25%（或现金为 0）才执行存取款，目标金额沿原版 nearest-even 规则取整。
