# M3.2 统一账本、付款、破产与胜负闭环

## 地址与目标模块

- 固定模块：`Rich4.exe` V3.11，SHA-256 `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`，32-bit x86，image base `0x400000`。
- 本步骤对应 `src/core/ledger.[ch]`、`game_state.h`、`turn_rotation.c` 与 `game_dispatch.c`。
- 原版锚点：通用付款 `0x41D2C6`、收费修正 `0x41D709`、破产清理 `0x40CD87`、资产估值 `0x4239B9`、胜负扫描 `0x41D89E`。

## IDA 与本地证据

- `../rich4/asm/rich4.asm:31195` 的 `fcn_0041d2c6` 按 flag `0x04` 选择银行优先，否则现金优先；收款 flag `0x01` 选择现金，否则进入银行。收款目标覆盖玩家、系统和大于 100 的公司/地产账户。
- 同文件约 31601 行的 `fcn_0041d709` 跳表给出 `god_info` 的 `1/2`、`0`、不变、`3/2`、`2` 倍分支。
- 同文件约 12401 行的 `fcn_0040cd87` 清活动态、关系余额、地产/设施 owner 与累计值、12 支股票、道具、卡片和 36 个事件占用，随后扫描剩余玩家。
- 同文件约 39255 行的 `fcn_004239b9` 按现金 + 银行 - 贷款 + 股票现价 + 地产/设施累计值估算资产。
- `../rich4/asm/rich4_ui_sale.asm:1926` 的出售提交最终调用 `0x41D2C6`；股票出售分支在约 1750–1810 行按数量和持仓价更新库存，出售清单记录携带已计算金额。core 因此复用股票当前价与地产/设施累计价值，不推导尚未确认的折价规则。
- 本轮 IDA MCP 核对了另一条“市场挂牌”链：`0x4246C5` 为每玩家最多 7 条、每条 12 bytes，创建时用首个空槽或同类型同 ID 槽；`0x4247D5` 撤销/成交后压缩后续记录并清空尾槽。`0x4255DA` 的 raw 类型为 1 股票、2 地产/设施、3 道具、4 卡片；买方现金达到报价后转移对应物品，并按报价调用玩家间付款。原生属性 raw ID 的地图映射起点为 land `0x7d1`、facility `0xfa1`；卡/道具挂牌 ID 是原始 1-based ID。`0x4284BE` 使用 Panel.MKF 73/74 展示人类市场，还包含 AI 随机挂牌、调价和购买分支。
- 当前核心已把 7 槽记录建入 `GameState.market_listings`，并实现创建、撤单、购买、AI 调价命令及事务性库存/资产/现金转移。SALE 工具栏现接入 app 状态机和 SDL 输入/绘制，可选择挂牌物品、输入报价与数量、浏览其他挂牌、撤单和确认购买；面板使用 Panel.MKF 73/74 作为资源背景，但 SDL 自绘列表/文字尚未做原版逐像素与时序对照。AI 已按 `0x4284BE` 接入挂牌、调价和购买分支；逐回放覆盖尚未建立，见 M3.10。

## 输入、输出和事务边界

- `rich4_ledger_pay` 是唯一付款入口。付款能由现金/银行完成时一次提交扣款、入账和 `GAME_EVENT_MONEY_TRANSFERRED`；玩家、系统与按股票稳定 ID 表示的公司账户均有独立余额。
- 2026-07-17 重新通过 IDA MCP 逐分支复核 `0x41D2C6`：现金与银行都不足时，不检查 `0x4239B9` 总资产，也不进入出售资产等待；它把实际可用的现金/银行转给收款方后立即调用 `0x40CD87`。此前实现的 pending liquidation 是非原版分支，且会令 SDL 路线永久等待，现已移除。
- `GAME_COMMAND_SELL_ASSET` 仍是独立出售命令；它不再被普通付款不足自动触发。
- 所有修改先在 `GameState` 副本和临时事件队列中完成；容量不足、越界、非 owner、溢出或淘汰收款方都会拒绝，原状态和输出队列不发生部分提交。
- 淘汰收款方在 raw `0x41D2C6` 内没有独立活动态保护。core 为保持“淘汰后资产恒为零”而将其定义为事务拒绝；这是明确的状态不变量，不把未知的 UI 上游约束伪装成原版分支。

## 清理和胜负

- 淘汰会释放全部普通地产和设施、按原版 `0x428E23(..., mode=0)` 将 12 支股票按现价卖回系统并恢复 `f8/f10`、再清卡片/道具、关系余额、贷款、持续状态和 36 个新闻事件占用。股票清理所得进入系统账户，不回到已淘汰玩家；所有权释放事件按类别聚合并携带释放数量，避免资产数量影响事务可提交性。
- `turn_rotation.c` 现在只按 `play_state` 判定淘汰，不再让位于 node 0 的淘汰玩家重新获得回合。
- 仅 `game_over == 0` 时可产生 `GAME_EVENT_GAME_ENDED`。最后一名活动玩家优先结束；否则复用 `0x41D89E` 的日期/目标资产候选。重复付款不会重复结束事件。

## 测试与置信度

- `tests/unit/test_ledger.c` 覆盖刚好够付、现金不足银行补足、银行优先、玩家/系统/公司目标、零收费、倍率和溢出、淘汰收款方拒绝、持有固定资产但流动资金不足仍立即破产、完整清理、事件容量回滚、最后玩家和目标结束一次。
- `tests/unit/test_turn_rotation.c` 固定 node 0 淘汰玩家也必须跳过；固定 replay 保持原事件数值协议不变。
- Windows：`make -B test sdl test-original-data`；Linux/WSL：`make test-sanitize`。（完成记录以本轮最终验证结果为准。）
- 置信度：付款顺序、收费倍率、资产组成、公司账户结算和破产清理为 `confirmed`；公司链接由地图 auxiliary 表确定性重建且不随设施 owner 改写，设施收费/生产的资源与逐像素演出仍属于 M3.4，股票日更及更广的普通交易规则属于 M3.9。
