# SDL 自定义存档对原版数据的覆盖矩阵

## 目的与判定标准

本表以 [原版主存档与时光机数据布局](original-save-data-layout.md) 为唯一
基线，逐块检查 SDL `GameSession`/`GameState` 的格式 12。这里严格区分：

- **直接保存**：有独立字段进入 codec，读写往返不依赖猜测。
- **等价重建**：文件不重复保存原始字节，但输入数据足以唯一重建；列出规则。
- **扩展保存**：原版不保存，SDL 为确定性 replay 或中途表现续接额外保存。
- **未证明等价**：原版保存了原始字节，SDL 只保存已理解投影，尚无证据证明
  未命名字节恒定或可重建。不能把这一类写成“已覆盖”。

当前格式保持为 12，不再为这次核对增加版本号。它包含以下原版状态修复：

1. `GameState.special_player_direction[5]` 直接保存原版特殊角色记录 `+0x09`。
2. 时光机由单个全局槽改为每名玩家一槽；玩家 0 沿用旧字段，玩家 1..3
   使用 `time_machine_other[3]`。自动采集只接受 `play_state & 1` 的真人玩家。
3. 挂牌记录 `+0x01/+0x0A/+0x0B` 按原版实现为月龄、资产类型快照、资产等级
   快照；月结更新月龄，购买前用快照判定资产挂牌是否失效。
4. 新局从公司记录 `+0x24/+0x28..31` 初始化董事长和前四名股东，而不是
   把股东排序全部清空。
5. `GameSession.map_access_flags[4]` 直接保存原版 `0x4990F0..0x4990F3`；
   码 2 的下一局设置保留它，码 3/码 1/主动返回主菜单的 `LABEL_5` 路径清空它。

格式 4..11 的单槽存档仍可读取；读取后按旧快照的 `current_player` 移入对应
玩家槽。恢复时只读取当前玩家自己的槽，并保留当前随机流，符合
`0x448544` 不恢复 C RNG 的边界。

## 主存档固定块

| 原版块 | SDL 对应 | 状态 | 说明 |
|---|---|---|---|
| 日期 4 字节 | `calendar_start_* + elapsed_days` | 等价重建 | `rich4_stock_calendar_date` 按同一公历规则得到当前年月日；原版不保存的 weekday 同样重算。 |
| stage / map / player count | `stage`, `map`, `player_count` | 直接保存 | 读档前还会用 stage/map 选择并校验地图。 |
| 四份普通角色记录 | `players[4]`、`presentation.actors[4]` | 语义字段直接保存，raw 部分见下表 | 即使 `player_count < 4`，四个 SDL 槽都进入 codec。 |
| 真人玩家数 | `human_player_count` | 直接保存 | 不能仅从当前存活角色重算，破产外层分支会使用开局总数。 |
| 五份特殊角色记录 | `special_player_*[5]` | 直接保存/等价重建 | 节点、前节点、方向、`+8/+10/+11` 与四种状态全部覆盖；坐标由节点和移动表现唯一重建。 |
| 46 份动态对象 | `presentation.dynamic_objects[46]` | 直接保存 | 类型、节点、倒计时、关联玩家、飞行状态、坐标和速度均进入 codec。 |
| 玩家卡片/道具栏 | `players[].card_inventory/tool_inventory` | 直接保存 | 固定 4×15。 |
| 公共卡片/道具池 | `card_amount[]`, `tool_amount[]` | 直接保存 | SDL 道具目录有 13 项，原版主文件明确写出的前 8 项包含在内。 |
| 股票历史游标和 12×144 历史 | `stock_history_cursor`, `stock_history` | 直接保存 | 游标与数据同时保存。 |
| 4×12 玩家持股 | `player_stock_amount`, `player_stock_average_cost` | 直接保存 | 数量和第二个 32 位值均往返。 |
| 12 份股票记录 | `stocks[12]` | 直接保存 | 原版名称指针不是业务数据；SDL 不保存进程指针。 |
| 4×7 挂牌记录 | `market_listings[4][7]` | 直接保存 | 类型、月龄、项目 ID、整笔要价、股票数量、资产类型/等级快照全部保存；月结和失效检查与 `0x428475/0x42483E` 对齐。格式 4..11 装载时从所列资产重建此前被 SDL 当作 reserved 的两个快照字节。 |
| 当前行动玩家 | `current_player` | 直接保存 | 经过范围校验。 |
| 开局交通/地产周期/天数/胜利/资金规则 | `initial_traffic_index`, `land_period_index`, `day_limit`, `win_target`, `initial_fund` | 直接保存 | 不从当前玩家状态反推。 |
| 物价指数、经过天数 | `price_index`, `elapsed_days` | 直接保存 | 同时进入每个时光机槽。 |
| 已完成月数 | `calendar_start_* + elapsed_days` | 等价重建 | `rich4_stock_elapsed_months` 唯一计算；SDL 不维护第二份易漂移计数。 |
| 股市关闭状态 | `stock_market_closed` | 直接保存 | 另存 `stock_last_update_day`，这是 SDL 的幂等更新扩展。 |
| 初始股票总值×10 | `stocks[].f12` | 等价重建 | 原版 `0x49907C` 的非存读档引用只有新局初始化；值为 12 个基准价之和×10。 |
| 当前股票总值×10 | `stock_market_total_x10` | 直接保存 | 日更后写入。 |
| 当日市场扰动 float | 无独立字段 | 行为等价，不是字节等价 | 原版仅在日更函数内写后读；函数返回后没有影响未来状态的读取。SDL 保存日更后的每股趋势/价格与随机流，但不保留这一个已经消费完的中间 float bit pattern。 |
| 四张地图访问标记 | `GameSession.map_access_flags[4]` | 直接保存 | 对应原版 `0x4990F0..0x4990F3`。`0x4075C1` 语义在真人胜利的码 2/3 路径标记当前地图；码 2 跨下一局设置保留，返回外层菜单时清空。该字段只属于主存档，不复制进时光机。 |
| 12 个角色选择标记 | `players[].character` 可重建活动集合 | 活动局等价；外层编辑态未建模 | 开局提交后原版把选中角色的 `4` 改为 `2`、其余清零。活动局可由四个角色槽重建；开局界面尚未提交的编辑态不属于可存局面。 |
| 乐透奖池和 36 所有人 | `lottery_pool`, `lottery_owner[36]` | 直接保存 | 所有人按原版 one-based 编码保留。 |
| 监狱/医院八槽占用表 | 玩家关押状态 + `special_player_confinement` | 等价重建 | 普通槽由对应状态低 7 位非零得到；特殊槽 4..7 由前四名特殊角色的 confinement 得到；第五名特殊角色原版无探访槽。 |
| 新闻/命运游标和顺序表 | `news/fortune_event_cursor`, `news/fortune_event_order` | 直接保存 | 顺序表与游标同时保存；另外保存 SDL 两阶段事件续接。 |
| 地图旋转方向 | `presentation.map_direction` | 直接保存 | 不是由玩家方向代替。 |
| 地图 blob 长度与整块 blob | 路线、地产、设施、公司各语义数组 | 行为等价重建；非逐字节镜像 | IDA 写入审计确认运行期可变范围：路线 `+36..39`；地产 `+23..26,+28..29,+44..51`；设施 `+24..30,+34..35,+48..55`；公司 `+24,+28..31,+40..51`；特殊地点无运行期写入。SDL 保存这些范围的语义状态，其他字节由 stage/map 静态资源重建。 |

## 特殊角色、地图对象与时光机

- 特殊角色 `+0x09` 方向现在是 `GameState` 的持久字段，主局、特殊事件
  `pre_state` 和所有玩家时光机槽都会经过同一 `codec_GameState`。
- 特殊角色 X/Y 在静止时由路线节点唯一计算；移动中的亚像素位置、路径、帧和
  暂停状态由 `GameSpecialActorPresentationState` 额外保存。
- 原版 46×24 动态对象由 `dynamic_objects[46]` 保存；SDL 的道路放置物还有
  `tool_placed_objects` 语义副本，读写时两边都做地图范围校验。
- 每名玩家的 SDL 时光机槽保存完整 `GameState + GameFlowState`，以及原版
  快照确实包含的普通角色表现记录和 46 个动态对象。玩家 0 为读取格式 4..11
  仍保留旧的完整 presentation 容器，但格式 12 恢复同样只应用 actor/动态对象，
  其余 UI/模态瞬态由 `rich4_presentation_initialize` 重建。各槽包含自己的地图
  语义数组、特殊角色方向、股票、乐透和新闻/命运状态。
- 原版把无效槽的原始内存也写入文件；SDL 把无效槽规范化为 `valid=0`，不承诺
  保留无效槽中的垃圾字节。无效数据不参与原版恢复，也不属于可观察局面。

## SDL 的有意扩展

以下字段原版主文件不保存，SDL 为确定性或非阻塞架构额外保存：

- 单一 `ai_rng_state`，用于 deterministic replay；实际 LOAD/resume 仍按当前时钟
  重播种 live state，时光机恢复仍保留 live RNG。
- flow executor、路线事件队列和可保存的表现续接。
- 已命名地图几何投影、工具放置物语义状态、保险/月结/拍卖等非阻塞续接。

扩展字段不改变上述判定：原版存在而 SDL 既不保存、也不能唯一重建的数据，仍须
标为未覆盖，不能因为 SDL 另存了更多状态就视为补齐。

## 当前结论

当前局内 save/load 的原版行为相关内容已经逐块核对：特殊角色方向、每玩家独立
时光机、挂牌月龄及资产快照、公司董事长/股东排序和地图全部运行期可变字段均有直接
保存或有 IDA 支持的唯一重建规则。普通角色 `f58/f67` 和地图剩余 raw/padding 已证明
在固定参考可执行文件中不参与运行期状态变化，因此不再列为“未知遗漏”。

仍不能宣称 SDL 文件与原版 `SAVE?.DAT` **逐字节相同**：原版会连同进程指针、静态
地图字节、padding 和无效时光机槽垃圾一起整块写出，SDL 有意保存规范化业务状态。
四张地图访问标记现在也按原版主存档边界直接保存，并已接入终局拼图、码 2
跨局保留以及外层菜单清空流程。至此，本清单没有尚未分类或未覆盖的原版业务状态块。
