# Action 6/7/8/15 点券小游戏与百货/货栈

复核日期：2026-10-22。小游戏状态机位于 `src/app/point_minigame_flow.c`，
SDL 资源适配位于 `game_loop_point_minigame_adapter.c`，绘制位于
`render/game_point_minigame_render.c`。完整特殊格列表和其余
action 的反编译记录仍以 `rich4/docs/special_place.txt` 为准。

## 公共进入音效表

`0x419884` 对 action 2..16 读取 `byte_475299[action]`，但该 byte 是
以 `0x48234A` 为基址、步长 8 的音效记录槽位，不是 `Effect.MKF` 资源号。
原表 action 2..9、14..16 的值为 10，该记录首字段是资源 43；action
10..13 的值为 16，该记录首字段是资源 48。因此：

- 新闻、命运、监狱/医院探访、彩票、三个点券小游戏、银行 STOP、商店及魔法屋等
  action 2..9、14..16 公共进入音效为 `Effect.MKF[43]`；银行 PASS 不经过
  该 STOP 入口，因此不播放这项音效。
- 点券 +50/+30/+10 与赠卡 action 10..13 的公共进入音效为
  `Effect.MKF[48]`。

这也解释了此前把表值 10/16 直接当资源号时，点券格、卡片格和同类特殊格
会一起播放错误音效。

## 托管小游戏结果（2026-10-12 复核）

`0x415215`、`0x4154DC`、`0x4155FC` 判断玩家 play-state 低字节是否为 1；
托管真人的值为 5，与 AI 一样进入公共块 `0x415457`。原版随机获得 50..69 点，
用 `0x463797` 的“得點券%d點”调用 `0x440CAC(...,2000)`，随后从
`0x48084A + character*0x6C` 的前两个台词指针随机选一条，以 type 0
调用 `0x44EF41`。action 7/8 直接跳入这同一公共块。

SDL 核心结算发出 `GAME_EVENT_POINT_MINIGAME_AUTOMATIC_RESOLVED`，携带点数和
台词选项；`route_event_flow.c` 将它接入 `point_minigame_flow.c` 的结果展示。
展示 2000 ms 后播放该角色对应的奖励台词，期间暂停回合推进，不再加点或抽取 RNG。
复用既有 `automatic` 保存字段记录已结算结果及台词选项，不改变存档字段布局。

## action 5：医院探访

`0x43E9A4` 为入口，真人 callback 是 `0x43DA27`，底图和人物来自
`Panel.MKF[65]`，特殊人物获救动作来自 `Panel.MKF[64]`。原 callback 的
100 ms timer 不是一次性的入场延迟，而是同时推进交互阶段和护士局部动作：

- 打开后以 `Panel[65].chunk2` 在 `(8,8)` 建立护士气泡，播放
  `#0127 / Speaking[127]`；台词至少保持 2000 ms，语音未结束时继续等待。
  台词结束前左右键只跳过当前台词，不会选择病床或直接关闭。
- 可选择阶段才响应 `0x475C64` 的八个 `147×102` 病床命中框。hover 使用
  `Panel[65].chunk3`，从病床左侧展开姓名、“保释点数”和 30/300 点费用；
  callback 本身没有 hover 音。
- 点数不足仍在护士 `chunk2` 气泡中播放 `#0002 / Speaking[2]`，不是中央
  通用静态提示。YES/NO 的 hover、确认和拒绝音分别沿用 `Effect[0]/[1]/[4]`。
- YES 后先播放护士 `#0129 / Speaking[129]`，台词结束才扣点并提交释放。
  普通玩家直接清住院状态；特殊人物还会以 `Panel[64].chunk0..3` 锚定
  `(420,450)`，按病床顺序播放被救台词
  `#0124/#0125/#0123/#0126`（Speaking 124/125/123/126）。
- 释放后的下一个 100 ms tick，或可选择阶段右键退出时，把护士从
  `Panel[65].chunk4` 左姿态切到 `chunk9` 右姿态，再播放
  `#0130 / Speaking[130]`；送别结束后 callback 才关闭。
- 护士手臂动作使用 `chunk5,6,5`（左）或 `10,11,10`（右），每帧 100 ms；
  说话期间的表情/口型在 `chunk7/8` 或 `12/13` 与底图裁片之间随机切换，
  保持 `rand()&7` 个 timer tick。SDL 使用独立的 15-bit MSVCRT 序列驱动
  这些纯表现随机数，不污染玩法 RNG。

SDL 因此把医院释放拆为“护士同意 → 释放提交 →（特殊人物被救台词）→
护士送别 → 关闭”，并保留普通玩家没有额外被救台词的原版差异。语音表冻结在
`src/data/character_speech.[ch]`，表现状态位于 `GameSession`，不会进入权威
`GameState` 或存档。

action 7 是点击上升气球的 `Panel[91]` 游戏，action 8 是鼠标横向控制接物的
`Panel[92..111]` 游戏；名称与图标不得互换。真人分支由 route executor 冻结在
STOP 事件，SDL 完成展示后提交最终点券或结束商店；非真人 action 6..8 仍使用
原版 50..69 点自动结算分支。

三个真人小游戏进入 callback 后分别切换固定 BGM：action 6 使用
`playmid(12)` / `MIDI13.MID`，action 7 使用 `playmid(11)` /
`MIDI12.MID`，action 8 使用 `playmid(10)` / `MIDI11.MID`；退出小游戏后
恢复大地图播放列表。

## action 7：七彩气球

- `Panel[91].chunk0` 为底图，chunk `type+1` 为 12 类气球；最多 16 个并行对象。
  callback 使用 100 ms timer、150 tick。
- 每个空槽每 tick 独立 `rand()%1000`：0..19 生成类型 0..4，20..27
  生成类型 8..5，28..29 再按 `0x475039` 生成 9/10/11；其余不生成。
  出生横坐标是 40、120、…、600，且同列 y>300 时不可重叠；上升速度来自
  `0x475004`。
- 类型 0..8 加 `type+1` 分，9 翻倍，10 减半，11 在立即结束、暂停 20 tick、
  加速、减速、清零、翻倍中随机选择；总分上限 999。普通气球命中框为
  ±22×±30，类型 6 以上为 ±18×±26；结束时等待仍在场对象完成，再保持结果
  2000 ms。
- 音效：公共进入 `Effect[43]`、生成/上升 helper `Effect[19]`、扫描未命中
  `Effect[20]`、命中 `Effect[21]`。callback 没有取消分支。

## action 8：喜从天降

- `Panel[92]` 是 640×480 RGB555 底图；`Panel[93]` 是财神、`[94]` 是小龙；
  `Panel[95..99]` 依次为宝箱、钱袋、元宝、金币、炸弹；`Panel[100+character]` 是当前
  角色；`Data[526]` 是炸弹碰撞 FLC。
- callback 使用 50 ms timer、360 tick。角色初始 `(320,380)`，鼠标横坐标与
  角色相差超过 8 px 时每 tick 左右移动 10 px；碰撞框直接取当前移动 chunk
  的 hotspot/宽高，严格判断物体锚点在矩形内部。先碰撞，再推进下落和角色移动。
  初始方向 0 不接取；进入行走后，鼠标距角色 ≤8 时保留原方向/行走帧。
  鼠标基准减当前 x 超过 8 时移到 0，小于 -8 时移到 639，角色本 tick
  使用移边前的采样坐标。没有额外的角色 20..620 限制。
  第一幅场景后等待 10×50 ms，再完整播放 `Panel[78]` 的 20×114 ms READY/GO；
  360 tick 从开场结束后开始。失去激活时不推进。
- 普通物类型概率来自 `rand()%20`：类型 3 为 9/20、2 为 6/20、1 为 3/20、
  0 为 2/20。初始 y=100、竖直速度 -16，每 tick 加 2、上限 16；y≥130 后
  五类速度为 `{24,18,15,12,15}`。水平曲线使用
  `trunc((startX-320)/210.0*260.0-(startX-320))`，按单精度
  `max(y-130,0)/250.0` 插值。绘制用 `32768*(1+t)` 的 16.16 缩放，
  热点保持原尺寸；旋转帧为 8 帧循环，更新后 y>380 即移除。
- 财神以状态 0/2/3/4 控制右走/转左/转右/左走，每步 12 px；行走前五阶段
  按保存的 0..4 阶段投放一次，第六阶段决定继续或转身。越过中线后每轮
  `rand()%4==0` 转身，110/530 强制转身。小龙只在财神越过中线、向外行走时
  以 `rand()%10>=7` 触发，在另一半屏幕的 160..299 或 360..499 取固定 x。
  小龙第八次推进投弹、十二次推进退出；已开始的小龙在超时后仍可投弹。
  全部物体共用 16 槽，槽满直接放弃投放，不消耗普通物类型随机数。
- 普通计分为 `10*c0 + 5*c1 + 3*c2 + c3`；炸弹停止 `Effect[24]`，播放
  `Effect[15]` 和 `Data[526]`，方向归零、禁止继续接物，保留已有财物分数。
  爆炸每 50 ms 解码一帧，共 8 帧；动画完成后的下一 tick 结算，场上已空
  的公共条件也可提前进入结算。时间归零后停止常规投放，已有物体继续处理，
  可继续接物或撞炸弹。正常结果 `<40`、40..49、50..59、≥60 分别用角色帧
  1/2/0/3，炸弹固定帧 4。无 999 分钳制，结果保持 2000 ms 后才入账。
  `0x41B152` 的点券为 16 位加法；结算一次后关闭事件，保留回绕行为。
- 音效：公共进入 `Effect[43]`、投放阶段 `Effect[22]`、对象循环
  `Effect[24]`、炸弹 `Effect[15]`。22/24 在小龙投弹时开始，最后一颗炸弹落空
  停止 24，普通财物接取不额外发声。callback 不处理点击或取消。
- 回归：`python scripts/make_minimal.py test-catcher-minigame` 覆盖状态/投放/收尾、
  点券只入账一次及回绕、缩放透明与裁剪，以及原版十二角色双向 266 张行走帧的碰撞框。

## action 15：百货/货栈

入口 `0x42E931`、真人 callback `0x42D37F`。买卖辅助函数为卡片卖出
`0x42D145`、道具卖出 `0x42D1B2`、卡片买入 `0x42D237`、道具买入
`0x42D272`；页面重建在 `0x42D299`，卡片/道具库存面板生成在
`0x441B0A`/`0x447C6E`。

### 完整流程

- 进入时播放一次 action 公共 `Effect.MKF[43]`。若 6001..7999 的公司记录
  owner 是当前玩家，先在卡片和道具间二选一：卡片按公共库存数量加权，
  道具只在前 8 种可售道具中按库存数量加权；卡槽满时替换价值最低的卡。
  显示“欢迎董事长光临／送您……！”1500 ms 后，再按礼物商店价选择该角色的
  获赠台词和 `Speaking.MKF` 语音。完成这段进店前置流程后，
  `0x42ECF4` 调用 `sub_4549CF(6)`，将背景音乐切换为商店专属
  `MIDI07.MID`；离店后 `0x42ED0F` 调用 `sub_454BCC` 恢复大地图播放列表。
- 正常进店先播放当前页欢迎词。只有页面尚未建立时才说欢迎词：欢迎气泡及语音
  完全结束后，左商品板从 x=-222、初速 +40 飞入，库存板从 x=640、初速
  -80 飞入；50 ms 一步，两边速度每步分别减 3/7，钳制到 x=5/227 后立即
  播放挑选提示。再次切回已加载页时既不重复欢迎词，也不重复飞入，只在下一个
  50 ms timer dispatch 播放挑选提示。欢迎、滑动、提示、错误和告别阶段隐藏
  软件光标并禁止交易，只有 active 阶段显示光标。
- 欢迎、挑选提示、失败反馈或告别气泡存在时，`0x42D37F` 的
  `WM_LBUTTONDOWN` 会调用 `sub_44EE18(1)`，立即停止当前语音并结束该段等待；
  这次点击只负责跳过，不会穿透到商品交易，也没有独立 Effect 音效。
- 卡片页把公共库存中的每一份卡片都作为一个抽选候选，按库存权重无放回抽取
  6..15 行；道具页依次列出公共库存仍有数量的前 8 种道具。工具库存面板把
  所有非零工具紧凑排列，每种只占一个格，并显示“×数量”。
- 商品和库存都在 `WM_LBUTTONDOWN` 成交。买卡要求点券足够且卡槽未满；
  买道具要求点券足够且该工具少于 9。成功购买会扣点券、扣公共库存，并把原
  商品名称和价格原位改画为 `0xA0A0A0` 灰色；商品行仍可见但不能再次点击，
  不是清空或压紧列表。卖出一次移除一张卡或一个道具，玩家得到
  `floor(商店价×0.9)`，对应物品回公共库存。
- 每笔卖出向公司记录 `+0x28` 与 `+0x2C` 各累计“商店全价”，每笔买入各
  累计“商店价×10”；这是买卖 helper 的返回值，不是玩家点券净变化。
- 页签和退出键在左键按下时切 pressed 图，只有在同一控件上松开才执行。
  页签按目标页是否已加载，分别执行首次的“欢迎→滑入→挑选提示”或重复进入
  的“仅挑选提示”；退出键播放当前页告别词，同时将卡片页/道具页店员的左臂
  替换成 chunk 3/19 的挥手姿势，等文本/语音结束后关闭。这里有挥手换帧，
  但不存在退出滑出动画。`WM_RBUTTONUP` 会停止当前店员语音并立即关闭。

### AI 分支

- 第一轮卡片出售保留 `0x42EDD4` 的原版槽索引行为：读取 `byte_47FDF9[slot*8]`，而不是持有卡 ID 的难度；差值为 2 时卖出该槽持有卡，压紧后重查同槽。道具仍按道具 ID 判断 `AI 难度 - AI 性格 == 2`。
- 若此时点券低于 100，再卖出持有卡片中商店价最低的一张、每种重复道具
  超过 1 的部分，以及与当前机车/汽车交通状态对应的全部交通工具。
- 以卖出后的点券分别建立两个独立预算：卡片预算
  `floor(points/2)`，道具预算 `points-floor(points/2)`。卡片候选按公共
  库存份数展开，过滤难度差 2 和超预算项，再按商店价降序购买，直到预算或
  15 个卡槽耗尽。
- 道具预算不受卡片消费影响。先在未持有且当前未使用的情况下尝试机车、汽车，
  两者使用严格的 `price < budget`；随后按零基索引
  `{7,1,6,0,3,2}` 各尝试买一个，使用 `price <= budget`、数量上限 9、
  公共库存非零和难度差不为 2 的条件。
- AI 的所有买卖同样把 helper 返回的营业额累计到公司记录
  `+0x28/+0x2C`。

店员动画由 callback 的 50 ms timer 驱动，`byte_48C348` 每次翻转，只有
翻为 1 时更新可见帧，因此有效步长约 100 ms。`n512_0` 的低 nibble 是
上半脸 idle 状态：

- 初始状态为卡片页 3、道具页 4；分别随机选择 chunk 4..6 或 23/24。
- 选到与上次不同的帧后转入状态 0并保持当前图。状态 0 每步取
  `rand() >> 10`：结果 0 时进入四步序列，结果 1 时回到随机状态，其余继续
  保持。因此两种转换各为 1/32，而不是固定每步切帧。
- 四步序列才是 `0x4755B8={7,8,7,5}` 和
  `0x4755BC={21,22,21,23}`；它属于 idle 上半脸动画，并不由语音开始。
  当步索引到 4 时，`0x42D902` / `0x42D9B7` 只把状态写回 0，不重画
  上半脸，因此卡片店员会保留最后画出的 chunk 5，道具店员会保留最后画出的
  chunk 23；直到后续状态 0 转入新的随机帧并实际重画为止。

嘴部是另一套状态，是否活动直接读取 `sub_44EF3B()` 返回的气泡时间戳。
气泡存在时，每个可见步以 `rand() >> 11 < 4`（1/4）概率选择 chunk
10/11 或 26/27，保持 `rand() & 7` 步（0 修正为 1），然后画 chunk 9/25
复原；气泡关闭后若仍在保持期，会继续倒数到复原。这里“说话”跟随整个气泡
生命周期，而不是每 100 ms 强制轮播一组嘴型。上半脸与嘴部必须独立保存和
覆盖，百货商店不使用 FLC 资源。

### 原版绘制与文字参数

- `sub_44EC30` 把 chunk 15 的气泡锚定在 `(120,10)`，文本偏移为
  `(-20,0)`。`sub_44ECB6` 因而把两行文本的中心锚点算为 `(235,119)`，
  使用 20 px、深色、style 2、字符间距 1、水平/垂直居中。
- 商品文字先画入随左板移动的运行时表面。卡片名称/价格锚点分别为
  `(90,83+24*i)` / `(194,75+24*i)`；道具为
  `(90,92+48*i)` / `(194,84+48*i)`。换算到最终屏幕时还要加左板
  `(left_x,10)`。名称使用 anchor 2，`$价格` 使用右对齐 anchor 1；
  两者均为 20 px、白字深色效果、style 3。
- `0x441B0A` 的卡片库存名称位于运行时表面
  `(45+80*col,33+56*row)`，同样使用 20 px 白字深色效果。`0x447C6E`
  会紧凑排列所有非零道具；图标热点位于
  `(29+80*col,33+56*row)`，“×数量”右对齐于
  `(79+80*col,23+56*row)`，数量为 1 时也显示。
- 点券框先在 `(230,246)` 按资源热点绘制 chunk 37，再以
  `(310,257)` 为右侧锚点绘制十进制点数；字体参数为 20 px、白字深色效果、
  style 3，而不是 SDL 位图数字。

## AI 小游戏结果提示坐标

2026-10-17 经 IDA Pro MCP 实时核对三个入口 `0x415215`、`0x4154DC`、
`0x4155FC`：自动分支共用 `0x415457`，在 `0x41548E` 调用
`0x440CAC(text, 2000)`，未置横向平移标志。资源加载点 `0x408087`
从 Data.mkf 句柄 `0x48A0E4` 读取 517，保存到 `0x48BAD8`；
`0x4191EA/0x4191FB` 确定提示锚点 `(220,140)`。
原始证据见 [反编译及指令记录](2026-10-17-ui-turn-order-ida.json)。

`rich4/asm/rich4.asm` 中 `0x419192..0x419223` 按 Data[517]
chunk 5 的内部锚点构造提示矩形，显示锚点为 `(220, 140)`。

结果提示未设置横向平移 100 像素的等待参数高位。
