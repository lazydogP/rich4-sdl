# M3.6 道具系统证据与 13 项清单

## 地址、布局与实现边界

- `0x49915c`：四名玩家共 60 bytes 道具数量表，每人 15 个 byte；前 13 项对应道具，最后 2 项按原版存档原样保留。
- `0x447D97`：真人/AI 使用道具总入口；真人面板枚举 13 项数量，AI 经 `0x420E9A` 后进入同一 handler 表。
- `0x475dd5 + original_id * 4`：原版 one-based handler 指针寻址式；ID 1 的实际指针槽为 `0x475dd9`。
- `0x40E033`：地图动态对象分配；类型 `0x10/0x11/0x12` 分别使用原版槽 16..25、26..35、36..45。
- `0x40E14D`：动态对象移除和路线节点关联清理。
- `0x41B42D`：到达节点后的动态对象分派；`0x41BCEB`、`0x41BE5F`、`0x41BFD2` 分别处理路障、地雷、定时炸弹。
- 目标实现：`src/core/tool.[ch]`、`src/core/route_movement.[ch]`、`src/core/game_dispatch.c`、`src/core/game_state.h`。

本次已用 IDA Pro MCP 重新复核固定 V3.11 的 `0x446AFB`、`0x446FBC`、
`0x447428`、`0x447ACE` 四个 deferred handler，以及 `0x445E4D`、
`0x446AE8`、`0x40AC7B`、`0x40DD1F`、`0x418EBD`、`0x44808A`、
`0x448544` 等共享前置。结论同时对照 `rich4/asm/rich4.asm`、独立 tool
handler asm、`rich4_tool_table.c`、`rich4_ui_use_tool.asm` 和
`rich4/csrc/tools_ui.c`。目录、库存、放置物、交通、选择 UI 和原四个
deferred handler 的调用顺序均为 `confirmed`。本轮又复核了
`0x445F88..0x446221` 的 50 ms 边缘滚屏、方向向量表 `0x4751B0`、
四向 cursor 资源 34/40/38/36，以及特殊 actor 8 的 Data[521]/[522]。

## 通用事务和状态模型

- `GamePlayerState.tool_inventory` 是精确的 `uint8_t[15]`，四名玩家合计 60 bytes；数量求和只统计前 13 项，保留槽仍随 `GameToolSnapshot` 往返。
- `GameState.tool_amount[13]` 是独立公共供给表，按目录初始化为 ID 1..8 各 10、ID 9..13 为 0。使用 ID 1..8 后按 `0x445AA2` 补回公共供给；ID 9..13 只减少玩家库存，不补公共池。
- `UseTool` 先检查活动玩家、库存、AI 难度、目标种类、注册节点范围、可放置标记、已有对象和对象槽，再在 `GameState` 副本及暂存事件队列中提交。效果、消费或事件任一步失败均不改原状态。
- 地图适配层必须通过 `rich4_tool_set_route_targets` 注册真实路线节点和已证实的可选集合；核心不会猜测未解析地图的“合理可放置”节点。
- SDL 实际移动循环现已调用 `rich4_route_move_commit_tool_events`，一步移动与到达节点的放置物触发处于同一事务。路障/地雷返回 stop 并清零剩余步数；定时炸弹返回 pass 并附着玩家。
- `rich4_tool_advance_step` 处理附着炸弹的每步倒计时、同格玩家转移、归零后 5 天住院，以及工程车经过 7 个住宅/商业聚落后恢复原交通方式。
- 范围效果命中 16/17/18 型放置物时复用 `0x40E14D` 的清理语义：公共路障/地雷/定时炸弹供给各回补一份；附着的定时炸弹同时清除玩家反向槽。附着炸弹没有路线 node 时按绑定玩家的当前位置参与区域命中。
- `GameToolSnapshot` 已升级为版本 2，除库存/放置物外还保存路线坐标、四向邻接、地产/设施坐标和机器娃娃临时 actor；导入前验证节点、重复占用、槽类型、机器人步数和炸弹双向引用。

## 放置物路线语义

- 原版路线记录 `+0x24` 的高位保存动态对象槽。`0x41B42D` 取槽、读取 `ref_00496d08` 的对象类型后分派。
- 路障分支 `0x41BCEB` 调 `0x40E14D` 移除对象并把移动状态清零，再以撞上路障的玩家读取 `_tool_strings[character][14]`、speech type 1 发言；因此核心返回 `GAME_TOOL_TRIGGER_STOP`，并发出该玩家的语音事件。
- 地雷分支 `0x41BE5F` 先移除对象，再进入角色清理/状态和动画链。顺序是 `Data[525]/Effect[82]` 爆炸、撞雷玩家 `_tool_strings[character][15]`、`Data[524]/Effect[92]` 送医、3 天住院状态与角色医院语音；`GAME_TOOL_TRIGGER_STOP_DEFERRED_EFFECT` 表示移动循环需等待整条表现队列后停止，不表示规则 deferred。
- 定时炸弹分支 `0x41BFD2` 把对象槽写入玩家 `+64`，对象 owner/attached byte 写玩家 one-based ID、计数写 `0x26`，并清路线节点显示关联。核心保留该对象槽、改为 attached 状态，避免把持久炸弹误作已销毁的一次性对象。
- 玩家已有附着炸弹时不吞掉新炸弹；对象留在节点。破产清理会移除该玩家已附着的炸弹并把 backlink 设回 `-1`。

### 区域效果前置的字段级语义

`0x40AC7B(radius,effect_mask,full_destroy,actor)` 的 `effect_mask=0x26`
分别覆盖住宅、设施以及人物/动态对象。`full_destroy=0`（飞弹）与
`full_destroy=1`（核子飞弹）必须保持如下差异：

- 住宅记录语义大小为 52 bytes。飞弹使等级 `+26` 减一；若特殊形态 `+24`
  非零，则同时把等级和特殊形态清零。核爆清 owner `+25`、等级 `+26`、
  形态 `+24` 和扩展字段 `+48`。
- 设施记录语义大小为 56 bytes。飞弹使等级 `+26` 减一，降至零时清类型
  `+24`；核爆清 owner `+25`、等级 `+26`、类型 `+24` 和扩展字段 `+52`。
- owner 存在时，飞弹每个受损建筑记 `30 × price_index`，核爆按原等级记
  `30 × price_index × level`；调用顺序发生在清字段之前。
- mask 命中的普通玩家先由范围函数设置临时受影响位；handler 随后逐玩家记
  `90 × price_index` 并送医院 3 天。临时位必须在一次效果事务结束时清理，
  不得留作持久状态。
- 特殊人物和动态对象分别走 `0x40CD07`、`0x43EC3F`、`0x40E14D`；哪些类型
  可移除必须沿用 mask 结果，不能简单清空全部地图对象。

## 原四个 deferred 道具的已完成链

### ID 1 机器娃娃

原版顺序为：消费 → 角色台词 → 复制当前 actor 位姿 → 保存原玩家 →
切换 current player 为 8 → `0x40DD1F` 启动自主移动。特殊 actor 移动期间使用
Effect.MKF[38] 循环音。`0x418EBD` 检测 current player 8 后从
`0x498E70` 恢复原玩家，并重新进入正常回合链。

完成标准不仅是“生成一个 actor”：必须证明沿途障碍处理、输入锁定、镜头跟随、
异常退出时玩家归还、回合 token 不重复，以及 actor 8 不进入普通玩家经济/地产事件。

2026-10-05 通过 IDA Pro MCP 复核并修正移动：

- `0x40C4C9..0x40C557` 扫描四邻接项，排除上一节点及
  `0x40000000 >> direction` 禁行位；有候选时消费一次 `rand()%count`，
  无候选则回到上一节点。首段也使用此规则，不沿用玩家预选的 `next_node`。
  SDL 使用现有 `ai_rng_state` 保存随机序列，事件提交失败时一并回滚。
- `0x40C5B9..0x40C6EE` 使用 `float(sqrt(dx²+dy²)*0.125)` 作为移动时长，
  整数部分为更新次数，中间帧以单精度坐标增量累加，段末对齐目标节点。
  复用 `route_geometry_flow` 的原版计算与 `0x401F98` 单个 pending pulse
  语义，SDL 更新间隔沿用游戏速度配置。
- `0x40C74A` 每次移动更新递增动画帧，渲染按 Data[522] 的每方向帧数循环，
  跨节点不重置帧数；`0x40BF4B/0x40BF69` 的 archive handle 是
  `0x48A0E4`（Data.mkf）。镜头和 sprite 消费同一逐帧世界坐标。
- `0x40D942` 在到达后的下一 pulse 处理节点并继续下一段；SDL 保留端点帧，
  核心对象移除复用 `0x40E14D` 的供给回补语义。完整动态对象清除、
  飞行表现及结束等待已在下述“机器娃娃清障与共用步数显示”增量接入。
- 回归覆盖：初始分岔随机选择、禁行位、死路掉头、九步预算、事件满回滚、
  按距离推进、迟到更新只消费一次 pulse、跨路段动画计数。

### ID 7 飞弹

原版顺序为：播放使用台词 → 以 mask `0x000300C0` 选择目标 → 取消则返回 0 →
消费 → `0x40AF12` 解目标坐标 → 聚焦 → `0x40AC7B(100,0x26,0,actor)` →
播放 `Data.MKF[528]` → 遍历受影响玩家记账并送医院 3 天 → 重绘。

完成标准包括：目标选择前不消费；效果、账务和医院状态原子提交；动画期间不接受第二次
UseTool；动画资源缺失时规则仍只提交一次；受影响集合不能由 SDL 点击半径临时猜测。

### ID 11 传送机

第一阶段 mask 为 `0x01200036`。真人选择的 original object ID 经规范化后进入四分支：

1. 住宅：第二阶段 mask `0x02090802`，搬 owner、等级/形态和扩展字段，源记录清零。
2. 设施：第二阶段 mask `0x02090804`，搬 owner、类型/等级和扩展字段，源记录清零。
3. 普通玩家或特殊 actor：第二阶段 mask `0x02090001`；清旧节点 occupancy，在目标
   节点选择可用出口/方向，更新节点、坐标、方向和 occupancy。若移动当前玩家，先调用
   `0x44808A` 保存时光机快照并重置移动状态。
4. 动态对象：第二阶段同样选择路线目的节点；清旧节点显示关联，修改对象 node/方向，
   再把对象类型位写入目标节点。

任一级取消都返回 0、不消费；成功后才刷新地图并消费。实现前必须先冻结 original
object ID 与 typed domain 的转换表，并为“目标已占用、出口不可用、第二阶段取消、
事件队列不足”建立全状态不变测试。

### ID 13 核子飞弹

原版顺序与飞弹相同，但选择 mask 为 `0x000400C0`，调用
`0x40AC7B(-1,0x26,1,actor)`，动画为 `Data.MKF[530]`。`radius=-1`
表示原版范围构造器定义的核爆全集，不得在 SDL 侧擅自解释为任意固定像素半径。
建筑走完全清空分支，命中的活动玩家仍记账并送医院 3 天。

## 2026-10-05：到格、障碍与停步结算的串行顺序

本次以 IDA MCP 的 `0x40D7C4`、`0x41B42D`、`0x418E7F`、
`0x40C912`、`0x41982D`、`0x450CED`、`0x45144F` 为依据修正 SDL：

1. `0x40C05C` 完成一步、扣步数并设置 `byte_48BB00`；**下一个逻辑 tick**
   才调用 `0x41B42D`。普通中途格的处理结束后，同一个 tick 可以开始下一步。
2. 到格先检查路过银行：动作 14、仍有步数、非梦游且格上动态类别与路障不同，才打开银行。
   然后自然停步才检查乞丐：`0x40D293` 返回最低编号的其他占格玩家，不会跳过
   活动玩家继续寻找后面的乞丐。提示等待 1500 ms，随后付款和迁移乞丐。
3. 已附身炸弹先减计数。减到零则在原持有者身上爆炸、送医 5 天并结束到格处理；
   非零才考虑转交给最低编号的其他占格玩家。
4. 再处理该格动态对象。路障无需步数为零；地雷、炸弹拾取、神明、狗的普通玩家
   分支要求自然停步。路障/地雷移除通过 `0x40E14D` 对应逻辑归还公共供给。
   新拾取炸弹保持 38，不在同次到格扣减。拾取对白来自 `0x480D9A + 104*character`，
   speech type 2；十二角色 Speaking 编号为 249、265、281、297、313、329、345、
   361、377、393、409、425。
5. 最后一步撞路障：到格 tick 已把 EA2 切为空闲、EA5 设为 5；对白结束后等待
   5 次递减。途中撞路障：handler 仅清剩余步数；下一个 tick 才切空闲并设 5，
   再等待 5 次递减。途中路障不会回头重跑自然停步的乞丐分支。
6. 5 tick 后由 `0x40C912(1)` 判断能否结算；住院、睡眠等阻止结算时返回 `0x83`
   （3 tick 后交棒）。可结算则进入 `0x41982D`：动作码优先；梦游跳过非零动作。
   动作 0 且 raw object 非零走 `0x41B077` 公共尾部，地产交易后才执行
   `0x40F381` 神明建筑效果，最后返回 `0x88`（8 tick）；raw object 为零及其他
   地点动作返回 `0x80`（下一 tick 交棒）。土地公取得所有权不播放购买成功音效。

逻辑 tick 为 `0x401F98` 的 20 ms 回调每 6/4/2 次产生一个布尔脉冲，即
120/80/40 ms。对白、动画和面板内不会补跑多次逻辑更新；模态返回保留一个待处理
脉冲。SDL 使用已序列化的 `turn_wait` 表达这些阶段，未增加存档字段。

动画资源读取沿用已核实的 `dword_48A0E4 = Data.mkf`。`0x450CED` 从 FLC +6
读取帧数、+16 读取帧间隔；`0x45144F` 连最后一帧也等待，没有额外的 160 ms 尾停。

62×100 = **6200 ms**；Data[532] 狗 38×114 = **4332 ms**。
