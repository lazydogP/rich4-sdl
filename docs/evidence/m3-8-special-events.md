# M3.8 新闻、命运、魔法屋与特殊事件证据

## 调度、索引与恢复边界

- 固定模块为 Rich4.exe V3.11（SHA-256 `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`）。2026-08-03 以 IDA Pro MCP、`../rich4/asm/rich4_fortune.asm`、`../rich4/asm/rich4_magic_house.asm` 和 `../rich4/csrc/fortune.c` 交叉复核；本轮另逐条跟踪了新闻 `0x475E24` 的 36 个 callback、命运 `0x475EF0` 的 49 个物理 callback，以及 `0x43D593/0x43EC3F/0x40D375` 的收容与失踪演出。
- 新闻入口 `0x44B6DF` 使用 36-byte 顺序表 `0x499090` 与 cursor `0x4990E0`，经 `0x448BE2` 过滤；命运入口 `0x44DB81` 使用 37-byte 顺序表 `0x496B38` 与 cursor `0x4990B4`，经 `0x44BB4B` 过滤。`0x448B81/0x44BAEA` 都按 `rand()%remaining` 加“扫描第 N 个未使用项”生成排列，不是 Fisher-Yates 的倒序交换实现。
- `core/rng.[ch]` 新增显式 `Rich4Rng` 状态 API，同时保留旧全局 wrapper。`rich4_special_event_sequences_init` 精确复现上述排列算法；新游戏通过注入的 stream 初始化两张表，SDL orchestration 取出全局 stream、执行排列后再提交推进后的 state，因此没有复制 seed 后产生第二条随机序列。最终 RNG state、两张排列、cursor 和当前选择都进入 `GameSpecialEventSnapshot` v1，坏排列、越界 cursor、非法 family/phase/target mask 在临时状态上拒绝。
- `core/special_event.[ch]` 将选择、phase 0、展示请求、phase 1 分开。`GAME_EVENT_SPECIAL_EVENT_PREPARED` 记录逻辑 ID、解析后的物理 ID、资源 ID和 family；`PRESENTATION_REQUESTED` 记录 Panel/可取消性；`COMMITTED/CANCELED` 是恢复路线队列的唯一完成边界。事件队列不足时原状态逐字节不变。
- 路线 dispatcher `0x41982D` 的 jump table 已确认 raw `0x1772/0x1773/0x1780` 分别调用新闻、命运、魔法屋。三类入口均已接入路线执行器：新闻/命运收到 `PRESENTATION_REQUESTED` 后进入定时展示，期间 cursor 冻结；新闻满 2400 ms、命运满 1600 ms 后由演出层内部提交 phase 1，不向真人或 AI 显示确认框。魔法屋会先产生合法目标条件；真人使用 `Panel[18..20]` 选择 12 项动作。AI 若自身在目标组固定选动作 6，否则取 `rand()%11` 并把 6 改成 7，因此不会在该分支选择动作 6 或 11。
- `0x41982D` 的首要分派依据是路线记录 `+0x24` 低字节 action，不是 raw object ID。对八张 V3.11 `Map.MKF` 的实际扫描确认：绝大多数 action 1..13、16 节点的 raw object ID 为 0，只有银行/商店和少数医院/监狱节点带对象记录。因此 SDL 的路线事件生成与 core executor 都以非零 action 覆盖 object-family 分类；否则这些格子会被错误当作“无对象”而没有 STOP 反应。回归测试使用 raw ID 0 的原版节点形态覆盖新闻、探访、小游戏、彩票、奖励、赠卡和魔法屋。

## 命运

- `0x44DB81` 与新闻相同，先 callback phase 0、展示、再 phase 1，没有取消整次命运的路径。`0x44B896(0,1)` 读取玩家投资修正（`+70`），用于冒贷、银行拒绝、股票损失、卖股与付款；`(1,1)` 读取地产修正（`+72`），用于旅行、绑架、车辆损失、住院、卖卡/道具与入狱。负面事件在修正值 `>100` 时阻止，`50<r<=100` 时消耗一次 `rand()&1` 决定正常/阻止，`r<0` 返回加倍，其余正常。收入事件使用 `(0,0)`，把阻止和加倍含义对调。ID 0/1/4/5 不调用修正函数。银行拒绝、股票损失、车辆损失和变卖库存的 callback 不把返回 2 重复应用到其效果。

  该 helper 与 `sub_456418` 一样会减去 chunk hotspot，区别是
  `sub_4563F5` 会复制零色像素、整块不透明。奖池底框 chunk 9、眨眼
  chunk 3/4 和嘴型 chunk 5/6 也走同一个不透明 hotspot helper；chunk 1、
  2、7 和数字资源仍走透明 helper。
- 已售号码的 62×46 区域在 chunk 0 的源图上调用
  `sub_4552E7(...,-10)`。RGB555 每通道使用 `0x485C28` 的 32 项表，
  等价于 `floor((22*c+16)/32)`，不是在 SDL 展开的 8-bit 通道上直接乘
  `22/32`。
- 原版 callback 的 100 ms tick 同时驱动柜员 `3,4,3` 眨眼、首 tick
  奖池刷新，以及成交/取消后的 chunk 2 离场姿势。chunk `5/6` 是嘴型：
  仅当 `sub_44EF3B()` 报告发言气泡存在时才随机启动；气泡关闭后只允许已有
  hold 倒数并恢复，不会在静默状态新开嘴型。
- 柜员文本表是 `#0011..#0016`，对应 `Speaking.MKF[11..16]`。气泡至少
  保持 2000 ms，并在语音更长时继续等待；购买另播 `Effect.MKF[31]`，
  取消使用 `Effect.MKF[4]`。彩票 action 自身的公共进入音效按
  `byte_475299` 的槽位 10 解码为 `Effect.MKF[43]`。
- `sub_42F7FC` 的输入分支只接管 `WM_LBUTTONDOWN` 和
  `WM_RBUTTONUP`：左键按下可先跳过开场气泡，再用同一次点击选择号码；
  右键按下没有动作，抬起才取消。键盘消息进入 `DefWindowProcA`，不存在
  键盘/手柄确认。SDL 彩票 modal 会在事件分派前吞掉这些鼠标消息，不能再
  触发底层小地图拖动、旋转或顶栏按钮。

## 魔法屋

- `0x43380A` 真人路径读取 `Panel.MKF[18..20]`；`0x431842` 反复以 `rand()%12` 选择非空条件，`0x431CAA` 对最多四个目标逐人提交。动作表每项 16 bytes，动作 4 的文字指针槽为 `0x475724+4*16=0x475764`。完整资源与交互表见 [0x43380A 魔法屋专项](43380a-magic-house.md)。

### 新闻15：原版已知的零住宅候选 BUG

- 地址：资格判断 `0x448BE2(15)`，候选收集/演出 `0x44A453`。2026-10-13 通过 IDA Pro MCP 复核，`confirmed`。
- 原版资格判断先扫描住宅记录 `+26` 的等级，再扫描设施等级，任一非零即通过；后续 `0x44A453(0)` 只扫描住宅记录，按等级非零收集，然后在 `0x44A4A8` 执行 `rand()%count`。
- 触发条件：存在已建设施，但没有任何等级非零的住宅。资格判断通过，住宅候选数为0，后续整数取模除零。这是原版游戏 BUG，不存在转选设施的逻辑。
- 本地证据：[`rich4/csrc/news.c`](../../../rich4/csrc/news.c:22) 的 case 4/5/15 共用住宅/设施检查；新复核原文见 [IDA JSON](../../../rich4/docs/evidence/news15-stay-card-ida.json)。
