# AI 停格规则与 SDL 对齐

## 特殊格公共入场音与自动分支提示

原版 `0x419884..0x4198A1` 在停格 action 2..16 分派前播放公共音效，
没有真人/AI 条件；梦游在此前返回，公园 action 1 没有该音。
`0x475299` 保存音效槽位，`0x48234A + slot*8` 才是记录：
槽 10 对应 `Effect.MKF[43]`，槽 16 对应 `[48]`。
action 2..9、14..16 使用前者，10..13 使用后者。
银行经过入口 `0x41B5AB` 只调用存取款，不播放停格公共入场音；
停留时存取款和贷款页之间不重复播放。

自动分支保留以下地图提示，不打开真人操作面板：

- `0x43D550 / 0x43EBFC`：探访成功先显示“保釋%s”1500 ms，之后扣点券和释放。
- `0x415457`：三个小游戏共用 50..69 点券结果，提示 2000 ms 后调用角色发言。
- `0x436877 / 0x43694B`：实际还款/借款的姓名及金额提示 1500 ms。
- `0x436C1F`：银行经营者垫付资金缺口的提示 2500 ms。
- `0x42EA14 / 0x42EA23`：自有商店先显示赠礼 1500 ms、调用角色反馈，再自动买卖。
- `0x4339BD / 0x4339CE`：魔法屋先展示目标条件和动作 1500 ms，再执行效果。

彩票 AI 购买、商店普通自动买卖和银行普通自动存取款没有结果文字提示。
新闻、命运、点券奖励、赠卡共用原版展示路径。
奖励 FLC 的附加音效分别为 `Effect.MKF[98]`（点券）和 `[99]`（赠卡），
与公共入场音不同。文字等待 `0x440CAC -> 0x4528B9` 接受任意松键或左右鼠标松开；
奖励 FLC 的 flags=1，不允许据此跳过动画本身。

逐项行为及本次 IDA 原始结果见
[原版特殊格清单](../../../rich4/docs/special_place_ai_prompts.txt) 和
[IDA 反编译证据](../../../rich4/docs/special_place_ai_prompts_ida.json)。

## 2026-10-12：特殊格、道具放置与炸弹数字

本次通过 IDA Pro MCP 与 `rich4/asm/rich4.asm` 复核，修复共享 core、SDL AI 地图输入和视图层；已有正确规则保留。对应实现为 `route_event_executor_step_special.c`、`ai.c`、`game_loop_ai.c`、`game_view_model.c` 与 `map_renderer.c`。

### 特殊格

原版 `0x41982D` 按路线 `+36` 低字节分派；梦游时跳过非零特殊动作。交互分支以玩家 `+21 == 1` 为真人条件。银行经过/停留、医院/监狱探访、魔法屋已统一使用原始 `play_state` 低字节，避免托管真人仍进入交互面板。

| 动作 | 已复核的自动行为 | 原版地址 |
| --- | --- | --- |
| 1 / 2 / 3 | 公园无额外结算；新闻、命运执行相应事件 | `0x41982D`、`0x44B6DF`、`0x44DB81` |
| 4 / 5 | 有收容对象才抽探访门槛；性格读取 `+23`；普通人物点券须 >30，特殊人物须 ≥700，分别扣 30/300；只抽一次目标 | `0x43D304`、`0x43E9A4` |
| 6–8 | AI 统一随机获得 50–69 点券，不进入真人小游戏 | `0x415457` |
| 9 | 现金 >1000 才随机购买一个未售号码，扣 1000 并加入奖池 | `0x4315CC` |
| 10–13 | 分别奖励 50/30/10 点券或进入赠卡池 | `0x41982D` |
| 14 | 经过只存取款；停留先存取款再处理贷款；拒绝往来状态阻止两者 | `0x4379C9`、`0x436668` |
| 15 | 按原槽位难度与价格规则自动卖出/买入 | `0x42E931` |
| 16 | 随机非空目标组；包含自己则动作 6，否则 `rand()%11`，抽到 6 改为 7；先显示条件及动作 1500 ms，再执行效果 | `0x43380A` |

后续复查补齐了此前遗漏的 AI 魔法屋提示：原先只有自动结算，画面没有反馈。现已接入 SDL 共用事件展示链，并等待原版 1500 ms；详见 [魔法屋遗漏修正](43380a-magic-house.md#2026-10-12-sdl-遗漏修正)。

### AI 道具位置

`0x447D97` 预选目标后由 `0x420EEE(0)` 返回，AI 不经过真人鼠标选择器。特殊格的动作低字节不构成禁放条件。

- `0x409EF9` 按路线 `+36 & 0x00FFFF00` 排除占用，结合 29×29 世界格窗口和 440×440 投影表，按屏幕行顺序列出道路。
- 路障 `0x42107F` 先检查无分岔的前方四格（占用掩码 `0x003FFF00`），按无主地产/设施的资金与投资条件，或点券 >200 的商店格选点；失败再走反向六步与可见空格交集，选自有高收费住宅组。
- 地雷 `0x4213C5`、定时炸弹 `0x421574` 使用反向六步与可见空格交集；优先有人收容的医院/监狱。地雷的其他候选须为他人已拥有的住宅/设施，炸弹没有产权限制。
- 反向 `0x40B343` 从上一节点再走一步才记录首项；直线路段对应身后第 2–7 格，不能替换成单纯距离圈。分岔和重复节点保持原随机顺序。

本次修复：`tool_route_flags` 只保留地图输入，原先没有实时反映人物和新放置道具。选点现在合并普通人物、特殊人物、已放置道具，以及 SDL 提供的地面神明/狗/礼物等动态对象占用。附着人物的对象不单独占据地面格；已离开地图的人物不阻挡道路。`0x40838D` 附近设置人物的 `0x100 << player` 位，`0x40E13C` 设置动态对象槽 `<<16`，与上述两种掩码对应。候选被占用时继续扫描后续位置。

机器工人、传送机、飞弹和核子飞弹的专有选点策略保持既有实现，详见 [AI 道具证据](m3-10-basic-ai.md)。不带投影的 core-only 人工状态保留短路线 fallback；SDL 实际游戏传入地图投影与动态占用。

### 定时炸弹数字

2026-10-12 附身后不可见修复：IDA Pro MCP 复核 `0x41C001..0x41C03A` 与 `0x408F9F..0x4090BA`。原版拾取只清除道路记录上的对象关联，保留动态对象节点；附身绘制使用玩家坐标。SDL core 的 `tool_flow.c` 则把已附身炸弹的 `node` 清零，`rich4_app_sync_tool_dynamic_objects` 原样传给视图。共享绘制入口先前仅凭节点和飞行标志判断存活，误过滤了附身炸弹。现将 `attached_player != 0` 也作为有效状态，主地图和地图信息共用此修复。未改变收容隐藏、方向偏移或倒计时规则。

回归以实际 core→presentation 同步得到的 `node=0 / flight_active=0 / attached_player=1 / countdown=38` 为输入，覆盖移动、静止、可见队列及倒计时标志、收容隐藏和无节点解除附身后的过滤。修改前测试在附身入队断言失败；修改后 `python scripts/make_minimal.py test-render test-tool sdl --progress` 通过。尚未进行真实游戏窗口视觉验收。

- `0x41BFD2`：普通玩家无附着炸弹，且剩余步数为零时才拾取，初值 38。经过不停留不拾取。
- `0x41B697`：每完成一步减一，可转移给其他活动且未带炸弹的玩家，转移保留计数；归零爆炸并住院 5 天。没有按秒计时或额外减一的显示修正。
- `0x40829D` 的附着对象分支仅在玩家 `+50..+53` 全零时入队；只有附着 type 18 在 `0x408CB1` 加 `0x4000` 标志。地面炸弹保留普通对象 ID，飞行对象 ID 为零，均不显示数字。
- 大偏移由玩家 `+63` 的神明槽决定，不能把 `+64` 的炸弹槽算入；没有神明时用普通八方向偏移。
- `0x4098BD..0x409929` 直接画对象计数，锚点为炸弹位置的 `(x,y-60)`，16 像素、亮色 `0xF0F0F0`、阴影 `0x101010`、粗体居中。SDL 原有文字参数保留。

回归覆盖托管银行/魔法屋/探访、占用候选后的继续扫描、特殊格可放路障、地面/飞行炸弹无数字、附着炸弹偏移和收容期间隐藏。另将视图测试中旧总资产期望 355 改为 356：已有 `0x423A0A` 实现计算 `trunc(25+3*10.5)+300`，本次未修改资产结算。

验证：`python scripts/make_minimal.py test-ai-landing test-render test-machine-doll-unit sdl --progress` 通过，覆盖 AI、落点执行、炸弹拾取/递减/转移、动态对象和视图，并完成 SDL 构建。`test-unit` 仍被架构检查拦截：`game_loop_tool_animation.c`、`game_loop_tool_animation_update.c`、`game_presentation_dispatch.c` 三处已有平台层状态写入（与下方历史记录相同，本次未修改这三个文件）。不能据此宣称全量单测通过，也未进行真实窗口逐帧视觉验收。

## 2026-10-09：停格领域规则

复核日期：2026-10-09。依据为 IDA Pro MCP 当前原版 Rich4.exe 数据库；本轮仅修改已确认的停格领域规则，保留工作树中已有修改。

| 原版地址 | 本轮对齐内容 |
| --- | --- |
| `0x41982D`、`0x41D7D4` | 梦游状态禁止购地/升级；购买保留额为 `min(trunc(initial_fund*0.05),7000)*price_index`，余额必须严格大于保留额。 |
| `0x457DBC` | `__CHP` 写控制字高字节 `0x1F`，即向零截断；更正此前文档的 nearest-even 结论。 |
| `0x4379C9` | 银行当前/目标比例先存单精度；月初乘 1.5、月末乘 0.5，再仅替换越过 0/1 的目标。包括等号的 ±25% 门槛与零现金强制重分配。 |
| `0x436668`、`0x4239B9` | 银行拒绝状态阻止存取款与贷款；还款门槛按 `loan*1.1` 比较并保留原期限字段。贷款资产估值按完整股票报价乘数量，再逐次截断。 |
| `0x41D839` | 公司股发行购买保留额按 `trunc(initial_fund*0.3)*price_index`。 |
| `0x43D304`、`0x43E9A4` | 医院/监狱探访目标策略使用玩家 `+23` 性格，不能读取 `+17` 交通方式。 |
| `0x42EDD4` | 商店首轮卖卡按槽索引读取难度表，保留压紧后重查同槽的原版行为。 |
| `0x40B455` | 建筑公司 AI 按扫描顺序选自有、可升级住宅/设施中最高值，严格比较保留首个并列，无候选不回退其他玩家。仅选中空设施时随机类型。 |
| `0x41AAF0`、`0x41AAFC`、`0x40B110` | AI 自营建筑公司连续施工两次，达到等级上限则停止；他营一次，无董事长不施工。 |
| `0x41ABDA`、`0x41ABDE` | 旅行公司费用不乘骰子；自己旅行公司不转轮盘。保险公司自己持有时仍抽保险天数；无收费分支不生成通用费用。 |
| `0x419E63`、`0x444A60`、`0x44476A` | 落点收费按原外层门槛尝试免费/嫁祸，保留随机门槛与先选嫁祸目标再抽门槛的顺序；酒店不尝试免费卡。嫁祸允许选收费方。 |
| `0x40FBB8`、`0x41AF96` | 卡链后扫描神明 14/15 的代付者；旅行结果非零时即使免费仍转移旅行状态。地产/设施与公司收款分别保留其免付条件。 |

上述逻辑进入 SDL 使用的共享 core 与 route executor，不另加模拟行为。新闻、命运、奖励、彩票、魔法屋等已存在的停格分支本轮不重复改写；没有足够原版证据的表现细节不补占位实现。
