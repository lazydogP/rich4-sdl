## 原版入口位置

原版新局顺序为：加载地图资源 `0x407AD2`，执行后续新局初始化 `0x4190CF`、`0x4291D6`，调用本函数，设置 `0x46CAFC = 1`，然后进入 `start_game_loop(0)`。因此 Intro 是地图数据已就绪、首回合 dirty/landing 流程尚未开始时的同步过场。

## 资源装载与所有权

`0x415879..0x415911` 打开 `JUMP.MKF`，同步读取以下资源后立即关闭 archive handle：

| 保存位置 | MKF chunk | 数量 | 已确认用途 |
| --- | ---: | ---: | --- |
| `0x48BDB0` | `45` | 1 | 回退序列的场景 SPR/SMP；函数使用其多个子图块 |
| `0x48BDB4` | `46` | 1 | 回退序列开头、位置 `(180, 60)` 的公共 FLC |
| `0x48BD90[player]` | `47 + character` | `player_count` | 第一组逐玩家 FLC |
| `0x48BDA0[player]` | `59 + character` | `player_count` | 第二组逐玩家 FLC |

角色来自玩家记录 `0x496B7B + player * 0x68` 的无符号 byte。原式是：

```text
resource(group, player) = 47 + character[player] + group * 12
group = 0, 1
```

`0x48BD90` 起的 8 个指针在装载前清零。函数无论正常完成、AVI 分支直接结束，还是 FLC 被输入打断，最终都在 `0x415CAD..0x415D05` 关闭临时显示状态并释放 chunk 45、46 和两组所有玩家资源。

chunk 45 的子图不需要依赖主观美术命名即可完整描述调用行为：`resource+12` 是初始/中央场景图，`resource+24` 是结束场景图，`resource+36` 是流水段固定前景图，`resource+12+12*(character+3)` 是按角色选择的图。后一项在原缓冲区原地执行亮度 `-20` 后，以自身 hotspot 绘制。`sub_4563F5` 绘制完整 SMP，`sub_456418` 绘制传入的单个 SMP 子图，`sub_4562CC` 是带源矩形和目标矩形的裁剪拷贝；这些 helper 的像素职责已由其下层 `0x455B3A/0x455C52/0x455E24` 参数和循环复核。

## 音乐与音效

AVI 尝试前 `sub_454ACB` 关闭当前 `mid` MCI alias。AVI 返回后，不论是否进入 JUMP 回退，函数都会：

1. 由 EFFECT archive 装载音效表 `0x4750F8`。该表是 `(resource_id, sound_object)` 对：`(25, ...)`、`(26, ...)`、`(-1, ...)`。
2. 调用 `sub_454D91(1)` 选择音乐索引 0；MIDI 模式打开对应 `RICHxx.MID` 并 `play mid from 0 notify`，CD 模式播放 track 2。
3. JUMP 回退开始时，以表首项调用 `sub_4542CE`，即播放音效资源 25。
4. 清理时 `sub_454240` 对表中每个 DirectSound buffer 执行“若仍播放则 stop、随后 release”，并从 16 项已装载表注册表中移除该表。

`sub_4542CE(pair, flags)` 把 `pair[1]` 的 sound buffer 和 `pair[0]` 的资源号交给 `sub_4540D8`；后者设置播放位置、播放 buffer，必要时从资源号重新恢复丢失的 buffer，并应用当前音量。因此这里不是不明的“临时状态 helper”，而是已闭环的音效播放路径。

## AVI 选择与回退条件

`0x415919..0x41596F` 先初始化过场环境，然后调用 `sub_451677(filename, &0x4750FC, 1)`：

```text
if game_stage != 0:
    filename = "AIRPLANE.AVI"
else:
    filename = movie_names[game_map]
                 # FLYTW.AVI / FLYCHINA.AVI / FLYJP.AVI / FLYUS.AVI
```

`sub_451677` 用 MCI 的 `open avivideo!... alias vfw` 打开文件；第一次失败后会再以前缀目录重试。两次打开都失败时返回 `0`。成功时进入 AVI callback，结束后执行 `stop vfw wait` 和 `close vfw wait`，并把 callback 返回值交还调用者。

本函数只在 AVI 调用返回 `0` 时执行 `JUMP.MKF` 回退序列；返回非零时直接进入统一清理。因此 SDL 在没有 AVI backend 时应记录原版选中的文件，并进入 JUMP 回退，而不应同时声称 AVI 已成功播放。

## JUMP 回退序列

### 1. 初始场景与公共动画

`0x415975..0x415A0E`：

1. 锁定绘制目标，以 chunk 45 的 `resource + 12` 子图覆盖 `(0, 0)`，解锁并把整个 `640×480` 区域提交到显示面。
2. 启用本段临时显示状态。
3. 调用 `sub_45144F(chunk46, 180, 60, flags=3, override=-1)`。
4. `override=-1` 表示不覆盖资源头延迟；`sub_45144F` 逐帧调用 decoder，并按 FLC header delay 等待。
5. 若播放器因允许的鼠标按键或键盘抬起消息返回非零，立即跳到统一清理，不再播放后续段落。

`sub_45144F` 的原版可中断输入是 `WM_LBUTTONUP (0x202)`、`WM_RBUTTONUP (0x205)` 和 `WM_KEYUP (0x101)`，前提是全局允许中断；等待期间仍轮询消息。

### 2. 逐玩家流水段

`0x415A14..0x415BCD` 的循环条件是 `sequence_index <= player_count`。它不是简单地“每位玩家画完再播放同一人的资源”，而是一个前后相接的流水：

1. 以 chunk 45 的场景图在 `(180, 60, 220, 240)` 周围重建中央画面。
2. 若当前 `character != -1`：
   - 对 chunk 45 的 `character + 3` 子图做亮度 `-20` 变换；
   - 把 `resource + 12 + 12 * (character + 3)` 的角色图画到 `(270, 220)`；
   - 把 chunk 45 的 `resource + 36` 固定子图画到 `(150, 60)`。
3. 提交矩形 `(180, 60)..(400, 300)`。
4. 当 `sequence_index != 0` 时，先把音效表第二项（资源 26）注册为 FLC 帧回调，再播放第一组玩家 FLC：

   ```text
   sub_45144F(group0[sequence_index - 1], 0, 0,
              flags=0x14000003, override=-1)
   ```

   返回非零立即结束整个 Intro。
5. 提交底部矩形 `(320, 400)..(640, 480)`。
6. 把下一位玩家的角色送入下一次迭代；最后一次迭代使用 `character = -1`，只完成流水尾部，不再画角色子图。

`0x14000003` 的有效字段已完整拆开：bit 0 选择可锁定的屏幕绘制路径，bit 1 允许输入中断，bits 24..30 的值 `0x14` 指定第 20 帧回调。`sub_450F04` 在完成该帧、帧计数变为 20 后调用先前注册的 `sub_4542CE(&table[1], 0)`，因此每位玩家的第一组 FLC 会在第 20 帧播放音效资源 26。这里的 `0x14` 位于最高 byte，不是 bits 16..23 的背景合成字段。

### FLC flags 的完整机械语义

`sub_450CED` 和 `sub_450F04` 对 32-bit flags 的解释如下；Intro 只使用上文标出的字段，但其余字段也已复核，避免再把调用 flags 记为 opaque：

| 位 | 已确认行为 |
| --- | --- |
| bit 0 | 使用可锁定屏幕目标及运行时 pitch；也是 bits 16..23 背景合成模式的前置条件 |
| bit 1 | `sub_45144F` 允许鼠标按键抬起或键盘抬起中断 |
| bit 2 | 到末帧后把帧号和数据指针复位，持续循环 |
| bit 3 | 选择另一种目标/合成模式，并强制关闭 bit 0 |
| bits 4..7 | 非零时以 `10 * value` 覆盖 FLC header delay |
| bits 8..15 | 非零时作为总播放遍数；每到末帧递减并回到首帧 |
| bits 16..23 | 分配 `0x5E880` 临时背景缓冲，并在指定帧（值 255 表示每帧）保存区域、调用 `0x40829D(-1,0)` 重绘地图、再合成/恢复该区域 |
| bits 24..30 | 在指定帧调用 `sub_450CDA` 注册的音效 pair/参数 |
| bit 31 | 选择 pitch 880 的离屏保存/恢复路径，并令内部目标模式为 2 |

### 3. 结束背景与第二组玩家动画

`0x415BDA..0x415CA7`：

1. 以 chunk 45 的 `resource + 24` 固定子图覆盖 `(0, 0)`，提交整个 `640×480`。
2. 按玩家索引从 0 到 `player_count - 1` 播放第二组 FLC：

   ```text
   sub_45144F(group1[player], 0, 0, flags=3, override=-1)
   ```

3. 每个未中断的玩家动画之后提交底部条带 `(0, 440)..(640, 480)`。
4. 任一播放器返回非零时停止该循环，随后进入统一清理。

## 已确认顺序摘要

```text
load JUMP 45, 46, (47 + character), (59 + character)
close JUMP archive
stop old MIDI
try selected AVI
load EFFECT 25/26 and start music index 0
if AVI result == 0:
    draw chunk-45 initial scene
    play effect 25
    play chunk 46 at (180, 60)
    run pipelined character/group-0 sequence; play effect 26 at frame 20
    draw chunk-45 ending scene
    play group-1 sequence and update bottom strip
cleanup every loaded resource
```

## SDL 对照与测试要求

- 当前 SDL 可用 JUMP 回退替代缺失的 AVI backend；不得把 AVI 和 JUMP 两条互斥路径串成同时成功。
- FLC 默认使用各资源 header delay；只有经调用点确认的 override 才允许覆盖。
- 后续 characterization 应至少记录：4 个 stage-0 map AVI 名、stage-nonzero AVI 名、1/4 位玩家资源序列、三类中断点，以及所有角色资源公式。
- 当前固定 replay 只证明场景切换，不证明本函数的像素、矩形提交和逐帧时序完全一致。
