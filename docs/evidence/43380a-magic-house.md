# 0x43380A 魔法屋：行为、资源与交互清单

## 证据边界

- 固定模块：`Rich4.exe` V3.11，SHA-256
  `5a90aee28ee5f7a5c3ba5cb935c9e55751a529c25fcd91208748a66293569550`，
  32-bit x86，image base `0x400000`。
- 2026-08-03 通过 IDA Pro MCP 重新复核 `0x43380A`、`0x431842`、
  `0x431CAA`、`0x41906A`、`0x432511`、`0x4325C2`、`0x440CAC`、
  `0x40B110`、`0x40AB4A`、
  `0x40C78C`、`0x441210` 和 `0x44476A`，并与
  `../rich4/asm/rich4_magic_house.asm`、`../rich4/docs/special_place.txt`
  交叉检查。归档 handle `0x48A05C` 为 `Panel.MKF`，`0x48A0E4`
  为 `Data.MKF`。

## 停留行为

`0x43380A` 先生成一个非空受术者条件。真人进入全屏模态魔法屋；
电脑自动选择动作，先在地图显示“受术者条件＋空行＋动作”提示 1500 ms，再结算。电脑不是从 12 项均匀选择：

1. 若受术者包含电脑自己，固定选择动作 6“得一张卡片”。
2. 否则取 `rand()%11`；若结果为 6，改成 7“向后转”。
3. 因此电脑的非自身分支不会选择动作 6，也不会选择动作 11“拍卖”。

### 2026-10-12 SDL 遗漏修正

再次通过 IDA Pro MCP 复核 `0x43380A`：AI 在 `0x43398F` 跳过条件文字开头的五字节 `#0046` 等语音标记，`0x4339AB` 用 `%s\n\n%s` 拼接条件与动作，`0x4339BD` 调用 `0x440CAC(text,1500)`，最后 `0x4339CE` 才调用 `0x431CAA`。这段不受动画开关影响，也不加载真人 Panel[18..20]、不切换 MIDI08。

此前 SDL AI 分支直接调用结算，完全没有发送展示事件；自动分支单测只断言没有真人交互请求，漏掉了这一可见反馈。因此即使后台得卡等效果发生，画面也像没有触发。

现在 AI 发送带预选动作的 `GAME_EVENT_MAGIC_HOUSE_REQUESTED` 并暂停 executor。app 进入 `RICH4_MAGIC_HOUSE_AI_NOTICE`，SDL 用普通地图消息框显示原版文字；满 1500 ms 后进入共用受术者提示/设施选择与结算流程。等待期间不重新抽签，不提前执行效果，不启动真人入场音效或模态音乐。真人请求保持原来的选择面板流程。

`test-magic-house` 覆盖普通 AI/托管玩家、动画开关、1499/1500 ms 边界、仅结算一次、等待期间随机状态不变，以及 SDL 共用的 app 事件分派。验证命令：`python scripts/make_minimal.py test-magic-house sdl --progress`。这属于调用链和构建验证，未进行真实窗口逐帧截图验收。

### 2026-10-12 真实地图 replay 续接

本轮再次用 IDA Pro MCP 核对 `0x43380A`、`0x431CAA`，并与 `rich4/asm/rich4_magic_house.asm` 的 `loc_00433994/loc_004339c5` 交叉检查：AI 先完成 `0x4339BD` 的 1500 ms 提示，再在 `0x4339CE` 调用共用效果；动作 1 在每个目标上连续执行三次命运（`0x431DBC`）。演出期间 executor 暂停是正确行为。

阻塞根因为 `test_real_map_bootstrap.c` 的演出 drain 只更新特殊事件、普通语音和保险，遗漏 `magic_house.active`。现调用已有 app `rich4_magic_house_update`，并将返回的命运展示事件接回特殊事件演出；不直接调用 core resume，也不清除等待标记。action 16 回归明确检查进入 AI_NOTICE/等待态，结束后魔法屋关闭且 executor 不再等待。无渲染回放沿用一帧资源替身，不能据此认定真人演出已验收。

`test-magic-house` 通过；完整 `test-replay` 已越过 action 16，但在后续资产目标长走的胜利原因断言失败，详见 M3 进度文档。本项演出续接阻塞已消除。

| 阶段/操作 | 资源 |

`Speaking.MKF[40]`“嘿～轮到你了！”不是无条件播放。`0x432647` 把
`animation ^ 1` 写入 `byte_48C3A5`；`0x4325C2` 只在该字节为 0，
也就是设置中的“动画”已开启时，才在条件播报结束后进入这句提示。关闭动画时
三段开场一并跳过，只保留一次 100 ms 的条件揭示 tick，条件播报结束后直接
进入动作选择；从 mask 13 返回并重播条件时也不会再次播放这句提示。

确认动作后，状态在 `0x432FDC` 切到 8 并播放 `Speaking.MKF[41]`
“天靈靈地靈靈～”。100 ms 定时器到 `0x432871` 时检测到状态 8 会直接返回，
不会进入 `0x43287E..0x432B4B` 的随机嘴型/表情分支；因此这句确认咒语期间
原版没有嘴部动画。语音结束后才播放 `Panel.MKF[20]`，该 FLC 播放期间
魔法屋 BGM 仍继续；FLC 完成、模态返回后才由 `sub_454BCC` 切回地图音乐。

## 可交互 UI：输入、变化与声音
