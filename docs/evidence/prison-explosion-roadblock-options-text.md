# 监禁光标、爆炸角色、路障消失与设置文字

核验来源：IDA Pro MCP 的 `Rich4.exe.i64`、`rich4/asm/rich4.asm` 与
`rich4/asm/rich4_ui_options.asm`；测试使用本地 V3.11 原始资源。

## 原版依据

- 监禁回合：`0x418C55 -> 0x40C912(0)`，监狱和医院状态经过可选角色
  台词、`0x440CAC(...,1500)` 后返回 0；只有人类正常输入分支在
  `0x418DC5` 调用 `0x402460(1)` 恢复光标。
- 地雷：`0x41BE8C` 移除地雷，`0x41BEA0 -> 0x40CD07` 切换受伤角色，
  `0x41BEBD` 从 Data.mkf 句柄 `0x48A0E4` 加载 525，播放参数
  `0x30001`、Effect[82]，接着播放地雷反应和住院反应。
- 定时炸弹：`0x41B6C4` 先递减倒计时，零时 `0x41B72E -> 0x40CD07`，
  同样播放 Data[525]，随后住院五天。`0x40CD07` 设置玩家 `+21` 的
  `0x40` 位；`0x40B93B:0x40B9CA` 加载 Data[128+21*character+18]。
  两条爆炸链均在爆炸位置显示受伤精灵。
- `0x451183` 先增加解码帧计数，`0x4512BF` 在参数指定的计数刷新地图：
  Data[525] 是第 3 帧，Data[524] 救护车是第 30 帧（`0x43ED59` 参数
  `0x1E0001`）。受伤精灵保留至该刷新边界；爆炸和住院反应台词期间
  也保留原位置，救护车返回后才同步小地图及镜头。
- 路障：`0x41BD08` 停止移动音效，`0x41BD18 -> 0x40E14D` 移除路障，
  `0x41BD26 -> 0x41D476` 立即刷新地图，再于 `0x41BD60` 播放角色反应。
- 设置文字：`0x411C73` 设置 20 像素字体，`0x411D32` 绘制主菜单和游戏内
  各三个按钮。`0x474B38` 表内锚点为 `(108,31)`、`(108,85)`、
  `(108,136)`，叠加 chunk 的 `(168,2)` 得到现有面板锚点。
  这六个按钮使用 20 像素字体。

## 爆炸、送医与小地图的阶段边界

2026-10-13 以固定 V3.11 IDB、`rich4/asm/rich4.asm` 和原始资源复核。
函数与角色台词表见 `rich4/docs/evidence/explosion_hospital_timing_ida.json`；
资源字段与 PCM 时长见 `explosion_hospital_timing_resources.json`。

- 地雷 `0x41BEA0..0x41BF09` 依次执行受伤、Data[525] 和踩雷反应；
  `0x41B8EF` 再进入住院三天。定时炸弹 `0x41B72E..0x41B786`
  执行受伤和 Data[525] 后直接进入住院五天，没有独立的踩雷台词。
- `0x43EC78` 先对准事故角色，`0x43EC93` 清除旧的 +50..+53 状态，
  `0x43ECA5` 播放送医前反应。该反应返回后，`0x43ECD3..0x43ED20`
  才修改节点、路径、坐标、住院天数与医院占用；此时尚不重绘小地图。
- `0x4512BF` 在救护车指定的刷新帧只调用 `0x40829D(-1,0)`：
  仍使用事故地点镜头重建主地图；没有调用 `0x416E6D`。所以小地图
  玩家图标和白框在整个救护车阶段保持事故位置，与主地图 actor 的
  刷新边界分别维护。
- 救护车返回后，`0x43EDA0 → 0x41D476` 以医院坐标更新小地图和
  主镜头。目标为当前 Actor 时，`0x41D4DE` 清除 `0x48BE18`，没有
  固定观察红框。事故地点台词的 `0x44EFBD` 也遵循这一比较规则。
- `0x44F1A6 → 0x4544F6(1000)` 等待语音结束，并把短语音补足至
  一秒；左右鼠标键释放或任意键释放可提前结束等待。爆炸和救护车
  的 FLC 调用不启用该跳过标志。动画关闭只跳过可选的救护车演出，
  仍保留状态提交、医院台词和理赔顺序。
- `0x43EDCB` 医院台词结束后，`0x43EDF8 → 0x44BA63` 才显示
  两秒理赔提示；提示返回后到账，最后执行 `0x43EE04` 累加本次
  住院天数。理赔金额为 `2000 * price_index * days`，地雷使用三天，
  定时炸弹使用五天；提示接受 `0x4528B9` 的释放输入跳过。

入狱和送医的平行入口、重复收容和调用者顺序见
[入狱与送医的原版时序](confinement-entry-timing.md)。
