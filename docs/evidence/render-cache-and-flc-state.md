# 地面、精灵取色与 FLC 状态

原版依据：`0x407A2C` 的子格镜头偏移、`0x408484..0x4084FE` 的地面
四角投影与 `0x473610` 可见格表；像素/调色板 helper 见 `0x455B3A`。
FLC 依据：2026-10-15 IDA MCP 复核 `0x450F04`，以及
[开局演出证据](415872-intro.md) 中的 `0x450CED`、`0x45144F`。

`0x450F04` 从 `0x476378` 读取下一帧，按帧长度推进这个指针，保留
像素及调色板状态。帧序号 `n255_0` 每次增加；循环/重复的末尾分支
才将指针恢复到 `0x48C858`。每次请求重复播放已显示的同一帧无需再次
解码；回退到较早帧须先恢复初始状态。

SDL 保留相同的帧索引、透明索引 0、调色板、裁剪和画面叠加顺序。
`rich4_flc_player_decode_to` 顺序消费差分帧，同帧复用，回退时重置。
派生解码缓存最多八个流、8 MiB 像素缓冲；仅持有 `GamePreviewAssets`
所拥有的资源视图。两个完整帧未使用的流释放，场景资源释放前清空缓存。
未属于该资源所有者的临时缓冲不进入持久缓存。

透明索引 0 使用本次绘制的背景；背景、位置和输出 surface 不进入
FLC 像素缓存。绘制直接读取对应背景像素，避免重复复制全屏及构造
source/composited 数组。

地面缓存仅复用相同 GND 资源、镜头坐标、方向、输出像素格式的绘制
结果，保持原有标量投影和纹理采样。覆盖掩码确保没有被地面写入的像素
仍取自本次背景。资源释放时清除，缓冲约 568 KiB。
SPR 调色板在绘制前映射，透明、主人颜色替换和明暗调整保持相同规则。
RGB555 转 RGB565 对应原版 0x451801 的直接位搬移：红、蓝原位宽保持，
绿色 5 位左移一位，新增的 RGB565 绿色最低位保持为 0；不经过 8-bit
中间量，也不存在绿色阈值 18。

验证入口：`python scripts/make_minimal.py test-render-equivalence`。
覆盖 160 次地面比较、九个实际 FLC 的顺序/重复/跳帧/回退/背景变化/裁剪、
九个同时使用的流的淘汰及资源释放；转色穷举 65536 个输入并核对两种格式。
标量测试参考只用于比对，不进入正式程序。

256 MB、无交换空间的 QEMU 使用相同按键和资源回放，1040 帧摘要相同，
66 个 BMP 文件逐字节相同。基线在 `build/miyoo/render-before`，
当前结果在 `build/miyoo/qemu256`，比较在 `build/miyoo/render-comparison.json`。
这些耗时属于 QEMU，不能作为真机帧率。

## 原版计时与等待

2026-10-15 使用 IDA Pro MCP 复核当前 V3.11 `Rich4.exe`；原始反编译、
表值和关键指令保存在 `build/miyoo/original-frame-timing-ida.json`。

| 路径 | 时间规则 | 原版锚点 |
| --- | --- | --- |
| 外层主循环、模态回调消息循环 | PeekMessage 轮询，无统一的每帧 sleep | `0x401B9C`、`0x4018E7` |
| 地图移动/动作脉冲 | 20 ms 基础定时器乘速度表 `{6,4,2}`，即慢/中/快 120/80/40 ms | `0x4020FA`、`0x401F98`、`0x46CB20` |
| 独立移动、地产交换动画 | 从本帧开始计时，绘制及提交后只补足到 24 ms；超过则不等待 | `0x40E669`、`0x40B4F8` |
| 选人常规动画、选人退场 | SetTimer 分别为 100 ms 和 50 ms | `0x404FAA`、`0x405CF3`，所属函数 `0x404E44` |
| 通用 FLC 播放 | 从解码前开始计时，解码/显示计入资源周期；达到周期或中断条件即结束等待 | `0x451490..0x451528`，所属函数 `0x45144F` |

`0x4020FA` 调用 `timeSetEvent(20,5,0x401F98,0,1)`：20 是基础周期，
5 是分辨率参数。回调读取速度配置 `0x497158`（IDA 名 `lpBuffer__14`），
按 `0x46CB20` 的字节表 `{6,4,2}` 累计回调次数，再置 `0x46CAFA=1`。
`WinMain` 在空闲消息分支看到该标志后调用 `0x40D7C4`；后者先清除标志。
这是单个待处理标志，不能将积压时间解释为须一次补执行多步。

`0x4192F7` 使用 `0x475110` 的位标志提交顶部、地图、右侧各块或整屏。
主循环只在该标志非零时调用它，并不是每次轮询都无条件重画整屏。
光标回调 `0x401F98` 在光标移动/换帧且相关条件满足时调用
`WaitForVerticalBlank`；不能据此把所有路径都解释成统一垂直同步帧率。

`0x40E97E..0x40E994` 的指令为：取当前 timeGetTime，减去本帧起点，
与 `0x18` 比较；小于时将 `0x18-elapsed` 传入 `0x45285E`。
因此，24 ms 是包含绘制/提交的总周期；例如绘制花 18 ms 只等约 6 ms，
绘制花 30 ms 则不再补等待。`0x40B4F8` 的两个移动分支相同。

`0x450CED` 从 FLC header `+0x10` 读取周期到 `0x48C870`；若 flags
bits 4–7 非零，则周期改成 `10 * ((flags >> 4) & 0xf)` ms。
`0x45144F` 在 `0x451490` 开始本帧计时，随后调用 `0x450F04`，在
`0x451516` 比较总耗时与该周期。直接由定时器回调调用 decoder 的事件
须保持各自 timer 规则，不能套用通用播放器周期。

原版等待 helper `0x45285E` 使用 timeGetTime/PeekMessage 循环，期间处理
音乐完成消息；它没有调用 Sleep。SDL 的实现可以用系统休眠避免忙等，
但应保持原版周期、可中断条件和更新次序。实机优化预算见
[Miyoo 内存与性能目标](../miyoo-memory-budget.md)。

## 事件资源的使用边界

2026-10-15 IDA MCP 复核 `0x4190CF`：从 `0x48A05C`（Panel.mkf）
取得通用界面 0–8；各事件面板沿各自 handler 取得。`0x418C55` 从
`0x48A0E4`（Data.mkf）取得 `559+character`，播放后在 `0x418CB2`
释放；最高级建筑 FLC 则由 `0x40B0CD` 取得 Data[523]，在 `0x40B10E`
释放。`0x415872` 的两组 Jump FLC 仅取所选玩家对应的资源，范围见
[开局演出](415872-intro.md)。

SDL 的 `game_lazy_assets.c` 将现有资源槽与这些已确认的 archive/index
绑定；检查可用性或使用原始图像时才取得 lease。动画计时查询只保存 header
帧数和间隔，查询结束归还解压字节。连续一个完整帧未再消费的图像释放；
先移除该字节缓冲对应的 FLC 派生状态，再归还 lease，避免地址复用后误用
旧 decoder。场景结束释放全部槽；永久菜单/光标资源与完整库存审计保持原有
所有权。原始资源存在性与可绘制标志分开保留，维持 AI 可见队列规则。

`test-render-equivalence` 增加 113 项面板的档案字节校验、释放后重载和
324 次全屏像素比较；其中 FLC 使用独立的旧标量解码/合成参考。
`test_miyoo_asset_scope` 在 QEMU 中两次装载每个面板，确认回到原有驻留量，
并验证 metadata 不持有图像字节。`test-frame-pacing` 用可控时钟覆盖实际
调度器的剩余等待、超时、较早动画期限、32-bit 时钟回绕与确定性回放时钟。

交互式 SDL 以原版光标 20 ms timer 为输入轮询上限，动画可请求更早的
唤醒期限；绘图与提交计入已花费时间，超时后不追加等待。各动画仍由原有
120/80/40 ms、24 ms、50/100 ms 或 FLC 周期推进。测试回放单独保留原有
16 ms 逻辑时钟，每帧不实际休眠；QEMU 另外用真实时钟运行标题对照和新局
到地图的交互路径，避免以确定性回放的零等待代替实际调度验证。
